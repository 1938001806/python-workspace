### 1. 09_rps_game.py —— 一个写得相当规矩的主循环

**做对的三件事**，值得专门表扬：

① 白名单校验（[09_rps_game.py:40-42](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/09_rps_game.py#L40)）：

if choice not in ["0", "1", "2"]:

这比 `isdigit()` 强，因为它同时挡住了「非数字」和「数字但不在范围内」两种情况。

③ 计数器 `round_count += 1` 放在循环**体内部末尾**（`:68`）。你在别的地方踩过这个坑，这里是对的。

「第 4 局」连续出现三次，正好证明 `continue` 跳过了 `:68` 的计数。这就是你想要的行为。

#### 问题 A：反斜杠续行 —— 用括号代替

[09_rps_game.py:60-62](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/09_rps_game.py#L60)：

```python
    elif (user_choice == 0 and computer_choice == 1) or \
         (user_choice == 1 and computer_choice == 2) or \
         (user_choice == 2 and computer_choice ==0):
```

`\` 续行有两个毛病：**后面不能有任何字符（连空格都不行）**，而且漏掉一个 `\` 时报错行号会指到很远。Python 里**圆括号内可以随意换行**，更保险：

```python
    elif ((user_choice == 0 and computer_choice == 1)
          or (user_choice == 1 and computer_choice == 2)
          or (user_choice == 2 and computer_choice == 0)):
```

#### 问题 B：三个分支可以化成一个取余公式

`names = ["石头", "剪刀", "布"]` 的下标顺序里，**每个都能赢它后面那一个（循环）**：0 赢 1、1 赢 2、2 赢 0。这正是「模 3」的味道。

```python
def judge(user_choice, computer_choice):
    """返回 "平局" / "你赢了" / "电脑赢了"。"""
    if user_choice == computer_choice:
        return "平局"
    return "你赢了" if (user_choice - computer_choice) % 3 == 2 else "电脑赢了"
```

**全枚举验证**（9 种组合，与原三分支逻辑逐对比对）：

```text
石头vs石头:平局  石头vs剪刀:你赢了  石头vs布:电脑赢了
剪刀vs石头:电脑赢了  剪刀vs剪刀:平局  剪刀vs布:你赢了
布vs石头:你赢了  布vs剪刀:电脑赢了  布vs布:平局
```

与原实现的不一致组合：**无，9/9 全部一致**。

> ⚠️ 这个公式**依赖 `names` 列表的顺序**。如果哪天有人把列表改成 `["石头", "布", "剪刀"]`，公式立刻反着判，而程序照样跑、不报错。所以改写之前先加上下面那个「全枚举自测」，它会在你改顺序时立刻抓住问题。这比留着三个 `and` 更值的，是它把「谁赢谁」这条规则收进了一个可测试的函数里。

#### 问题 C：退出分支和正常结束分支**行为不一致**

[09_rps_game.py:36-39](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/09_rps_game.py#L36) 中途退出：

```python
    if choice == "3":
        print("退出游戏，最终战绩：")
        print(f"你赢了{stats['玩家赢']}次，电脑赢了{stats['电脑赢']}次，平局{stats['平局']}次。")
        break          # ← 没有判定「最终胜者」
```

而 `:18-26` 正常结束时**会**打印「🏆 最终胜者」。同一个「游戏结束」，两条路径给出不同信息，而且那句战绩统计的 f-string 被复制了两遍。修法是抽成一个函数：

```python
def show_stats(stats, winner=True):
    print(f"你赢了 {stats['玩家赢']} 次，电脑赢了 {stats['电脑赢']} 次，平局 {stats['平局']} 次。")
    if winner:
        if stats["玩家赢"] > stats["电脑赢"]:
            print("🏆 最终胜者：你！太厉害了！")
        elif stats["玩家赢"] < stats["电脑赢"]:
            print("💻 最终胜者：电脑！下次加油！")
        else:
            print("🤝 势均力敌，最终是平局！")
```

**判断标准**：同一段话在文件里出现两次以上，就该变成函数——哪怕它只是一句 `print`。

把玩家输入的历史存进列表，然后用列表做统计（[10_add_game.py:15](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/10_add_game.py#L15)、`:27`、`:31`）：

nums = []

if len(nums) >= MAX_TIMES:        # 列表长度 = 已输入次数，不需要单独计数器

#### 问题 A：漏了 `.strip()`（实测抓到的真 bug）

[10_add_game.py:43](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/10_add_game.py#L43)：

```python
    choice = input("请输入一个 1~4 的数字：")        # 没有 .strip()
    if choice not in ["1", "2", "3", "4"]:
```

对照实测（同样输入「空格 + 1」）：

```text
# 10_add_game.py（无 strip）
请输入一个 1~4 的数字：❌ 输入有误，只能输入 1~4 的数字，请重新输入！

# 09_rps_game.py（有 strip）
请输入数字（0/1/2/3）：你出的是：石头        ← 正常接受
```

**同一个用户动作，一个文件接受、另一个拒绝。** 原因：`" 1" not in ["1", "2", "3", "4"]` 是 `True`，因为字符串带空格就不等于 `"1"`。

修法就是把 09 号那行照搬过来——**两个文件用同一套校验**：

```python
while True:
    choice = input("请输入一个 1~4 的数字：").strip()      # 补上 strip
    if choice not in ["1", "2", "3", "4"]:                # 保持列表白名单
        print("❌ 输入有误，只能输入 1~4 的数字，请重新输入！")
        continue
    user_num = int(choice)
    print(f"收到合法数字：{user_num}")
    break
```

> ⚠️ **但 `in "1234"` 有个真实的陷阱，别乱用。** 对字符串做 `in` 是**子串匹配**，不是逐字符比较。实测：
>
> ```text
> '1'  not in "1234" -> False   （接受，正确）
> '5'  not in "1234" -> True    （拒绝，正确）
> '12' not in "1234" -> False   （接受！错 —— "12" 是 "1234" 的子串）
> '0'  not in "1234" -> True    （拒绝，正确）
> ```
>
> 也就是说玩家输入 `12`、`23`、`1234` 全都会被当成合法出拳。**只有确定输入长度恒为 1 时才能这么写**（比如前面已经 `if len(choice) != 1` 挡过）。稳妥写法仍然是原来的列表白名单 `["1", "2", "3", "4"]`——它比 `in "1234"` 长，但不会背叛你。

#### 问题 B：「数字相同」那个 `else` 分支很容易被误认为死代码

[10_add_game.py:59-70](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/10_add_game.py#L59)：

```python
    if user_num + computer_num == 5:      # 和为 5 → 平局
    elif user_num > computer_num:         # 大的赢
    elif user_num < computer_num:
    else:                                 # 相等 → 也是平局
        print("数字相同，平局")
```

乍看像死代码（相等时不就都是平局吗），但**它是活的**：上面实测第 2 局 `2 vs 2`，和是 4 ≠ 5，就落到了这个 `else`。

不过这里暴露一个**规则设计问题**：两种「平局」的判定混在一起，而且 `和 == 5` 排在最前面会**掩盖胜负**。比如 `4 vs 1`：数字明明 4 大，本该玩家赢，却因和是 5 被判平局。上面实测最后一局 `1 vs 4` 的输出就是：

```text
你输入的数字是：1
电脑输入的数字是：4
结果：数字之和是 5，平局！       ← 按「大的赢」本该是电脑赢
```

代码没错，是规则本身自相矛盾。如果想让「和为 5」成为特殊规则，就该明确它优先于大小；如果不想，就该先判大小。**这类「逻辑都对，但规则打架」的问题，只有把真实输出逐条读一遍才能发现**——瞪代码看不出来。

#### 问题 C：判定顺序与 `print` 混在循环里

`if/elif` 链把「判定」和「打印」搅在一起，导致想单独测规则必须跑整个游戏。抽出来即可：

```python
def judge_add(user_num, computer_num, sum_is_draw=True):
    """返回 '平局' / '你赢了' / '电脑赢了'。"""
    if sum_is_draw and user_num + computer_num == 5:
        return "平局"
    if user_num > computer_num:
        return "你赢了"
    if user_num < computer_num:
        return "电脑赢了"
    return "平局"

for u in range(1, 5):
    for c in range(1, 5):
        print(f"{u} vs {c} 和={u + c} -> {judge_add(u, c)}")
```

16 种组合一次打全，「4 vs 1」这种被掩盖的情况会立刻显形。

## 二、`random` 家族速查（本类只用了 `randint`）

```python
import random

lst = [1, 2, 3, 4, 5]
random.randint(1, 6)          # 闭区间整数，两端都取得到 —— 09/10 用的就是这个
random.randrange(0, 3)        # 左含右不含
random.choice(["石头", "剪刀", "布"])   # 从序列里随机挑一个（更贴合本类场景）
random.sample([1, 2, 3, 4, 5], 3)      # 不放回随机取 3 个
random.shuffle(lst)                      # 原地打乱，返回 None（和 append 一样）
print(random.shuffle(lst), lst)          # -> None [3, 5, 2, 1, 4]  顺序变了但要用 lst 接
random.random()                          # [0.0, 1.0) 的浮点数
random.seed(7)                           # 固定种子 → 结果可复现，调试和测试必备
```

**`random.choice` 比 `randint` 更适合石头剪刀布**，因为「出拳」和「名字」不用再手动映射：

```python
import random

names = ["石头", "剪刀", "布"]
user_name = random.choice(names)
computer_name = random.choice(names)
```

**`random.seed()` 的实战价值**：本类脚本最难调试的就是「电脑随机出拳导致每次结果不同」。在开头加 `random.seed(7)`，每次跑出的完全一样，你可以放心改判定逻辑；改完再删掉 seed 恢复随机。

## 三、字典做统计的三种写法（由糙到精）

```python
# ① 你现在的方式：预先声明每个键（09_rps_game.py:5-9）
stats = {"玩家赢": 0, "电脑赢": 0, "平局": 0}
stats["平局"] += 1

# ② 不想预先声明，用 get 兜底
stats = {}
stats["平局"] = stats.get("平局", 0) + 1

# ③ 标准库专门干这事的 collections.Counter —— 最省
from collections import Counter
stats = Counter()
for outcome in ["平局", "你赢了", "平局", "电脑赢了"]:
    stats[outcome] += 1
print(stats)                 # Counter({'平局': 2, '你赢了': 1, '电脑赢了': 1})
print(stats.most_common(1))  # [('平局', 2)]  直接要「出现最多的那一项」
```

写法 ① 的隐含风险：**键名打错一个字（`"玩家赢"` 打成 `"玩家贏"`）不会报错，只是默默新建一个键**，最后的统计就少了一项。这是中文键名特别容易踩的坑。②③ 也挡不住拼错，但 `Counter` 至少能在你打印它时看到多余的键而发现异常。

**因此建议**：把「结果」的取值定义成常量，别散落字符串字面量：

```python
WIN, LOSE, DRAW = "你赢了", "电脑赢了", "平局"     # 只在这一行敲中文
stats = Counter({WIN: 0, LOSE: 0, DRAW: 0})
```
