## 一、09_rps_game.py —— 一个几乎写完整的回合制游戏

### 骨架

| 部分 | 位置 | 作用 |
| --- | --- | --- |
| `stats` | [:5-9](../09_rps_game.py#L5-L9) | 三个计数器：玩家赢 / 电脑赢 / 平局 |
| `round_count` + `MAX_ROUNDS` | [:11-12](../09_rps_game.py#L11-L12) | 已打局数 + 上限 |
| 顶部终局判断 | [:16-27](../09_rps_game.py#L16-L27) | 打满 5 局 → 算总账 → `break` |
| 输入与退出 | [:34-42](../09_rps_game.py#L34-L42) | `3` 退出；非 `0/1/2` 重来 |
| 胜负判定 | [:57-68](../09_rps_game.py#L57-L68) | 平局 / 三连 `or` 判玩家赢 / 否则电脑赢 |

### 实际运行

输入：`0 → 1 → 2 → 0 → 1`（电脑随机）

```text
===== 欢迎来到石头剪刀布大作战 =====

---第1局，请出拳 ---
0.石头
1.剪刀
2.布
3.不玩了，退出
请输入数字（0/1/2/3）：
你出的是：石头
电脑出的是：剪刀
结果：你赢了！🎉

---第2局，请出拳 ---
...
你出的是：剪刀
电脑出的是：石头
结果：电脑赢了！
...
===========游戏结束==========
总比分：你赢了1次，电脑赢了1次，平局3次。
🤝 势均力敌，最终是平局！
```

**为什么 1:1 却显示「势均力敌」**：终局只比较 `玩家赢` 和 `电脑赢`（[:21-26](../09_rps_game.py#L21-L26)），平局数不参与。1 胜 1 负 3 平确实是「谁也没领先」，文案没问题。

### 输入校验：这一版写对了

[09_rps_game.py:34-42](../09_rps_game.py#L34-L42)：

```python
choice = input("请输入数字（0/1/2/3）：").strip()

if choice == "3":
    print("退出游戏，最终战绩：")
    print(f"你赢了{stats['玩家赢']}次，电脑赢了{stats['电脑赢']}次，平局{stats['平局']}次。")
    break
if choice not in ["0","1","2"]:
    print("❌输入有误，请重新输入！")
    continue
```

- 先判退出，再判合法值，最后才 `int()`——顺序正确，`int("abc")` 永远不会执行。
- 非法输入 `continue`，**不消耗局数**，`round_count` 只在有效回合末尾 `+= 1`（[:68](../09_rps_game.py#L68)）。

### 胜负判定：能用，但可以压成一个公式

当前写法 [09_rps_game.py:60-62](../09_rps_game.py#L60-L62)：

```python
elif (user_choice == 0 and computer_choice == 1) or \
     (user_choice == 1 and computer_choice == 2) or \
     (user_choice == 2 and computer_choice == 0):
```

**逻辑本身是对的**：0 石头赢 1 剪刀，1 剪刀赢 2 布，2 布赢 0 石头。

但它把「石头剪刀布」的循环关系写死了三次。用取模可以压成一行：

```python
result = (user_choice - computer_choice) % 3
# 0 = 平局，2 = 玩家赢，1 = 电脑赢
```

全 9 种组合实测：

```text
石头 vs 石头 -> 平        石头 vs 剪刀 -> 玩家赢    石头 vs 布 -> 电脑赢
剪刀 vs 石头 -> 电脑赢    剪刀 vs 剪刀 -> 平        剪刀 vs 布 -> 玩家赢
布   vs 石头 -> 玩家赢    布   vs 剪刀 -> 电脑赢    布   vs 布 -> 平
```

映射记法：`2` 是「玩家赢」不是「电脑赢」——`(0-1)%3 = 2`，而石头赢剪刀。

> ⚠️ 三行 `or` 用了反斜杠续行。反斜杠后面**不能有任何空格**，否则语法错误。用括号包起来更稳：
> ```python
> elif ((u, c) in {(0, 1), (1, 2), (2, 0)}):
> ```
> 或者直接用上面的取模。

### 两个可改进点

1. **结算文案写了两遍**：[:18](../09_rps_game.py#L18) 和 [:38](../09_rps_game.py#L38) 都在拼「你赢了 X 次…」，改一处容易漏另一处。抽成 `show_stats(stats)`。
2. **随机不可复现**：`random.randint(0, 2)`（[:46](../09_rps_game.py#L46)）每次运行都不同。调试想固定结果时，在开头加 `random.seed(42)`；正式玩时再删掉。

### 字典计分的静默风险

`stats` 的键是中文手写字符串（[:5-9](../09_rps_game.py#L5-L9)）。如果哪次把 `"平局"` 打成 `"平剧"`：

```python
stats["平剧"] += 1     # 不会报 KeyError？会——除非预先声明过
```

当前是「先声明三个键」，所以打错会立刻 `KeyError`，这反而安全。**更危险的是用 `Counter` 或 `dict.get`**：

```text
Counter({'玩家赢': 1, '平局': 1, '电脑赢': 0})
```

Counter 对不存在的键会**静默新建并计数**，打错字不会报错，只是统计结果少了/多了。键名越自由，越要打印出来核对。

## 二、10_add_game.py —— 一条自相矛盾的规则

### 规则

[10_add_game.py:9-12](../10_add_game.py#L9-L12)：

```text
双方各输入一个 1~4 的数字，谁的数字大谁赢。
当两个数字之和正好是 5 时，这一局算平局。
总共只能输入 5 次，到第 5 次就判定错误，游戏结束。
```

判定顺序 [10_add_game.py:59-70](../10_add_game.py#L59-L70)：

```python
if user_num + computer_num == 5:      # ① 和为 5 → 平局（最高优先级）
    ...
elif user_num > computer_num:          # ② 比大小
    ...
elif user_num < computer_num:
    ...
else:                                  # ③ 相等
    ...
```

### 实测：3 vs 2 应该是玩家赢，却被判平局

输入 `1 → 2 → 3 → 4 → 1`，其中第 3 局玩家出 3、电脑出 2：

```text
--- 第 3 次输入（还剩 2 次机会）---
请输入一个 1~4 的数字：你输入的数字是：3
电脑输入的数字是：2
结果：数字之和是 5，平局！
```

3 > 2，按「谁大谁赢」玩家应赢；但 `3 + 2 == 5` 先命中，于是平局。**两条规则在同一局上冲突，代码选择了先写的「和为 5」**。这不是运行时 bug，是规则设计问题。要消除歧义，必须二选一：

- 方案 A：和为 5 只在「双方相等」时才成立（去掉最高优先级）；
- 方案 B：明确「和为 5 的优先级高于比大小」，并把文案改成「只要和为 5，不论大小都算平局」。

第二种更像你原本的意图，但现在的提示语还写着「谁的数字大谁赢」，两者矛盾。

### 终局文案也不严谨

打满 5 次后固定打印：

```text
你一共输入了 5 次数字，已经达到 5 次，判定错误！
```

哪怕玩家 5 局全赢，也显示「判定错误」（[:29](../10_add_game.py#L29)）。「输入 5 次」本意可能是「最多 5 次」，但实现成了「满 5 次必判错」。建议改成「本局结束」，再单独输出胜负。

### 实际终局

输入 `1 → 2 → 3 → 4 → 1`：

```text
=========== 游戏结束 ==========
你一共输入了 5 次数字，已经达到 5 次，判定错误！
你输入过的数字：[1, 2, 3, 4, 1]
数字之和：11
战绩：你赢了 1 次，电脑赢了 2 次，平局 2 次。
💻 最终胜者：电脑！
```

### 写得好的两处

1. **`nums` 同时承担「历史记录」和「已输入次数」**（[:15](../10_add_game.py#L15)、[:27](../10_add_game.py#L27)）。`len(nums)` 就是次数，不需要再维护一个 `count`，不会出现两套计数不同步。
2. **非法输入不进 `nums`**（[:45-47](../10_add_game.py#L45-L47) 先 `continue`，[:51](../10_add_game.py#L51) 才 `append`），所以「输入 5 次」只算合法回合。

### 一个和 09 不一致的地方

[10_add_game.py:43](../10_add_game.py#L43)：

```python

```

没有 `.strip()`。输入 `" 1"`（前面带空格）会被判为非法：

## 三、`random` 家族速查（本类用到的部分）

| 函数 | 返回 | 本类用处 |
| --- | --- | --- |
| `random.randint(a, b)` | `[a, b]` 闭区间整数 | 09 的 0~2、10 的 1~4 |
| `random.choice(seq)` | 序列中随机一个元素 | 11 篇的随机游走 |
| `random.seed(n)` | 固定随机序列 | 调试/复现 |
| `random.shuffle(lst)` | 原地打乱 | 洗牌类游戏 |

两个常见误区：

- `randint(0, 2)` 包含 2，`range(0, 2)` 不包含 2；不要混。
- `random` 是伪随机，**同一次运行内不重复播种就够了**；要复现实验结果，必须在**程序开头**播种，而不是每次调用前。

## 四、计分的三种写法（由糙到精）

```python
# ① 预先声明（09/10 现在的写法）
stats = {"玩家赢": 0, "电脑赢": 0, "平局": 0}
stats["玩家赢"] += 1

# ② get 兜底（键名打错会静默新建）
stats["玩家赢"] = stats.get("玩家赢", 0) + 1

# ③ collections.Counter（最省，但同样静默）
from collections import Counter
stats = Counter()
stats["玩家赢"] += 1
```

三种都能跑。①最啰嗦但**打错键会立刻 KeyError**，对学习阶段反而最安全。
