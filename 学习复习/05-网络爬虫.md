## 一、13_spider.py

### 实际输出（本次联网）

```text
正在发送请求...
✅ 网页获取成功！开始解析...

第1句名言；“The world as we have created it is a process of our thinking. It cannot be changed without changing our thinking.”
第2句名言；“It is our choices, Harry, that show what we truly are, far more than our abilities.”
...
第10句名言；“A day without sunshine is like, you know, night.”
```

10 条全部抓到了。下面看这一版还剩什么问题。

### 缺陷 1：UA 键名已经改对，但值里仍有拼写错误

[13_spider.py:6-8](../13_spider.py#L6-L8)：

```python
headers = {
    "User-agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) ApplewebKit/537.36 ..."
}
```

和旧笔记里的 `Uers-agent` 相比，**键名已经修正**。HTTP 头部名大小写不敏感，`User-agent` 与 `User-Agent` 都能发出去。实测服务器实际收到的头：

```text
status 200
UA header on request: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36
quotes: 10
```

注意 `request.headers` 里显示的是规范写法 `User-Agent`，值里的 `ApplewebKit` 被保留（大小写不同但服务器只做粗略识别，不影响本站）。同类问题在 `14_spider_save.py:7` 还有 `Chorme`（应为 `Chrome`）。

> 📌 仍然保留的教训：**字典的键、HTML 属性名、JSON 字段名——任何「字符串当标识符」的地方，打错都不报错**。曾经那个 `Uers-agent` 不报错、请求也成功，但伪装完全没生效。验证方法永远是回显 `response.request.headers`。

### 缺陷 2：失败分支会二次崩溃

[13_spider.py:21-22](../13_spider.py#L21-L22)：

```python
else:
    print(f"❌ 请求失败，状态码：{requests.status_code}")
```

`status_code` 在**响应对象**上，不在 `requests` 模块上。实测：

```text
requests.status_code exists: False
requests.status_code -> AttributeError: module 'requests' has no attribute 'status_code'
```

网络出错本来只是拿不到数据，结果错误处理自己先抛异常。改成 `response.status_code`。

### 缺陷 3：没有 `timeout`

[13_spider.py:11](../13_spider.py#L11)：

```python
response = requests.get(url, headers=headers)
```

不带超时，遇到挂死或慢速服务器会无限期卡住。永远加：

```python
response = requests.get(url, headers=headers, timeout=10)
```

### 缺陷 4：标点写错

[13_spider.py:19](../13_spider.py#L19)：

```python
print(f"第{i+1}句名言；{quote.text}")
```

用的是分号 `；`，应为冒号 `：`。程序不会提醒，只能读输出发现。

### 修正版（本次实测）

```python
import requests
from bs4 import BeautifulSoup

URL = "http://quotes.toscrape.com/"
HEADERS = {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
                         "AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36"}

response = requests.get(URL, headers=HEADERS, timeout=10)
print("实际发出的 UA:", response.request.headers.get("User-Agent", "缺失")[:40])

if response.status_code == 200:
    soup = BeautifulSoup(response.text, "html.parser")
    quotes = soup.find_all("span", class_="text")
    print("抓到条数:", len(quotes))                 # 一定要打印数量
    for i, quote in enumerate(quotes, start=1):
        print(f"第{i}句名言：{quote.text}")
else:
    print(f"❌ 请求失败，状态码：{response.status_code}")
```

实测：

```text
实际发出的 UA: Mozilla/5.0 (Windows NT 10.0; Win64; x64
抓到条数: 10
第1句名言：“The world as we have created it is a process of o...
```

`response.request.headers` 是「实际发出去的请求头」——用它回显一次，就能确认伪装生效，不用猜。

### 做得好的三处

1. **批量存盘**：先攒 `all_data`，最后一次性写文件（[:17-30](../14_spider_save.py#L17-L30)）。比每抓一条开一次文件好得多。
2. **`encoding="utf-8-sig"`**（[:30](../14_spider_save.py#L30)）：带 BOM 的 UTF-8，Excel 直接双击打开中文不乱码。代价是文件开头多一个 `\ufeff`，用 `csv`/pandas 读时通常会自动处理。
3. **用 pandas 落盘**：`DataFrame(all_data, columns=[...])` 给了明确列名。

### 问题 1：两个 `find_all` 按下标配对（脆弱）

[14_spider_save.py:14-21](../14_spider_save.py#L14-L21)：

```python
quotes = soup.find_all("span", class_="text")
authors = soup.find_all("small", class_="author")

for i in range(len(quotes)):
    quote_text = quotes[i].text
    author_text = authors[i].text
```

它假设两个列表**长度相同且顺序一一对应**。本站每个 `div.quote` 恰好一个名言 + 一个作者，所以现在没错；但只要页面里有一块缺作者，两个列表就会整体错位，而且**不会报错**，只是所有作者都配错了。

更稳的写法是按「块」取：

```python
for quote_block in soup.select("div.quote"):
    quote_text = quote_block.select_one("span.text").text
    author_text = quote_block.select_one("small.author").text
```

这样「名言」和「作者」从同一个父块里取，天生配对。

### 问题 2：提示语指向错文件

存的是 `quotes_pandas.csv`（[:30](../14_spider_save.py#L30)），提示语却让你打开 `quotes.csv`（[:32](../14_spider_save.py#L32)）。上一版留下的文案忘了改。

### 问题 3：没有 `timeout`，也没有失败细节

[:9](../14_spider_save.py#L9) 的 `requests.get` 无超时；[:33-34](../14_spider_save.py#L33-L34) 的 `else` 只打印「请求失败」，不给状态码。

## 三、翻页：为什么退出条件不能只看状态码

`quotes.toscrape.com` 的翻页规律：第 1~10 页各有 10 条，第 11 页返回 **200 但 0 条**。实测：

```text
page 2  status 200 quotes 10
page 10 status 200 quotes 10
page 11 status 200 quotes 0
```

如果退出条件写成 `if status_code == 404: break`，程序会一直抓到空页，永不停止（或直到内存爆）。**退出条件必须是「本页解析出的数据条数为 0」**：

```python
for page in range(1, 100):
    r = requests.get(f"{URL}page/{page}/", headers=HEADERS, timeout=10)
    if r.status_code != 200:
        print(f"第 {page} 页状态码 {r.status_code}，停止")
        break
    soup = BeautifulSoup(r.text, "html.parser")
    blocks = soup.select("div.quote")
    print(f"第 {page} 页 quote 块 {len(blocks)} 个")
    if not blocks:                 # ← 真正的退出条件
        break
    ...
```

同时加 `range(1, 100)` 这种**硬上限**，防止站点行为变化导致死循环。

## 四、`requests` + BeautifulSoup 最小必会集

| 需求 | 写法 |
| --- | --- |
| 发 GET（带 UA/超时） | `requests.get(url, headers=..., timeout=10)` |
| 检查状态码 | `r.status_code`；或 `r.raise_for_status()` |
| 看实际发出的头 | `r.request.headers` |
| 文本 | `r.text`（按响应编码解码） |
| 选择器 | `soup.select("div.quote")` / `soup.select_one("span.text")` |
| 按属性找 | `soup.find_all("span", class_="text")` |
| 取文字 | `.text`（或 `.get_text(strip=True)`） |
| 传查询参数 | `requests.get(url, params={"page": 2})` |

**外部数据（用户输入、文件、网络）一律当不可信**：请求要超时，状态码要判，解析结果条数要打印。

## 五、易错清单（本类真实出现）

| # | 现场 | 类型 | 对策 |
| --- | --- | --- | --- |
| 1 | `requests.status_code` | 错误处理自己崩 | `response.status_code` |
| 2 | 两处 `requests.get` 无 `timeout` | 可能永久卡住 | 一律 `timeout=10` |
| 3 | 两个 `find_all` 按下标配对 | 静默错位 | 按 `div.quote` 分块取 |
| 4 | 提示语说 `quotes.csv`，实存 `quotes_pandas.csv` | 文案错 | 文件名用变量，别在文案里重写 |
| 5 | UA 值里 `ApplewebKit` / `Chorme` | 拼写错 | 回显请求头，复制官方 UA |
| 6 | `第1句名言；` | 标点错 | 读输出 |
| 7 | 退出条件只看状态码 | 死循环 | 以「数据条数为 0」为退出条件 + 页数上限 |
| 8 | `import csv` 未使用 | 冗余 | 删掉 |
