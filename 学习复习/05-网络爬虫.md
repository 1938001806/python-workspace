### 缺陷 1：`"Uers-agent"` —— 拼错一个字母，伪装彻底失效（静默 bug）

[13_spider.py:6-8](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/13_spider.py#L6)：

```python
headers = {
    "Uers-agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) ApplewebKit/537.36 ..."
}
```

`Uers-agent` 少了一个 `d`（应为 `User-agent`）。**字典的键打错，Python 不会报错，只是这个键没人认识。**

我做了服务器侧对照实验（用 httpbin 回显服务器实际收到的请求头）：

```text
拼错时服务器看到的 UA： python-requests/2.34.2      ← 伪装根本没生效！
拼对时服务器看到的 UA： MyBot                        ← 你的值真的传过去了
```

**这就是「静默 bug」的典型**：程序照跑、结果照出（该站不拦 UA），你在屏幕上看不出任何异常，但你的伪装**一条都没落地**。等你哪天去抓一个会拦 UA 的站点，就会拿到 403，然后完全想不通「我明明设了 UA 啊」。

> 📌 **通用教训**：字典的键、HTML 的属性名、JSON 的字段名——**任何「字符串当标识符」的地方，打错都不报错**。这类代码必须有一段「把实际值回显出来看看」的验证，而不是只看程序有没有崩。

顺带：字符串值里的 `ApplewebKit` 也拼错了（正确是 `AppleWebKit`），`14_spider_save.py:7` 里还有 `Chorme`（应 `Chrome`）。UA 字符串本身打错一两个字符通常不影响（服务器只做粗略识别），但**键名**打错是致命的。

### 缺陷 2：失败分支会**二次崩溃**

[13_spider.py:22](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/13_spider.py#L22)：

```python
else:
    print(f"❌ 请求失败，状态码：{requests.status_code}")   # 应为 response.status_code
```

实测：

```text
requests.status_code -> AttributeError: module 'requests' has no attribute 'status_code'
```

**最坏的时候撞最烂的代码**：网络出问题本来只是拿不到数据，结果你的错误处理自己先抛异常。我把这段放进真实场景验证了一下——访问一个不存在的页面：

```text
状态码: 404 | response.text 前 40: <!doctype html> <html lang=en> <title>40...
```

状态码是 404，走 `else` 分支，然后那行代码立刻 `AttributeError`。修法是 `response.status_code`（状态码在**响应对象**上，不在模块上）。

### 缺陷 3：没有 `timeout`

`requests.get(url, headers=headers)` 不带超时，遇到慢速或挂死的服务器会**无限期卡住**。永远加上：

```python
response = requests.get(url, headers=headers, timeout=10)
```

### 修正版（实测通过）

```python
import requests
from bs4 import BeautifulSoup

URL = "http://quotes.toscrape.com/"
HEADERS = {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
                         "AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36"}

response = requests.get(URL, headers=HEADERS, timeout=10)
print("UA 键名确认:", [k for k in response.request.headers if k.lower() == "user-agent"])
print("服务器是否收到我们的 UA:", response.request.headers.get("User-Agent", "缺失")[:40])

if response.status_code == 200:
    soup = BeautifulSoup(response.text, "html.parser")
    quotes = soup.find_all("span", class_="text")
    print("抓到条数:", len(quotes))                # ← 一定要打印数量
    for i, quote in enumerate(quotes, start=1):
        print(f"第{i}句名言：{quote.text}")          # 中文冒号，不是分号
else:
    print(f"❌ 请求失败，状态码：{response.status_code}")
```

实测输出：

```text
UA 键名确认: ['User-Agent']
服务器是否收到我们的 UA: Mozilla/5.0 (Windows NT 10.0; Win64; x64
抓到条数: 10
第1句名言：“The world as we have created it is a process of o...
```

`response.request.headers` 是「**实际发出去的请求头**」——用它回显一次，就能确定伪装有没有生效。第一版这么验一次，以后就不用猜了。

> 顺便：`第1句名言；` 用的是分号 `；`，应为冒号 `：`（[13_spider.py:19](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/13_spider.py#L19)）。标点类错误和文案错误一样，程序永远不会提醒你。

### 缺陷 1：提示语说的文件名 ≠ 实际保存的文件名

[14_spider_save.py:30](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/14_spider_save.py#L30) 存的是 `quotes_pandas.csv`，`:32` 却让你「双击打开 `quotes.csv`」。上面输出证据里两件事同时发生，说明**文案是从上一版复制来忘了改**。

这类「提示语过期」的错误有个便宜的防法：**别在字符串里手写文件名，用同一个变量**：

```python
print(f"🎉 保存成功！打开 {OUT_FILE} 看看吧！")     # 永远一致
```

### 缺陷 2：`import csv` 是死代码

[14_spider_save.py:1](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/14_spider_save.py#L1) 导入了 `csv`，但全文用的是 pandas 的 `to_csv`，`csv` 一次都没用到。删掉——留着会让下次读代码的人（包括三个月后的你）以为有两种保存路径。

### 缺陷 3：`range(len())` 配对法有隐藏风险

[14_spider_save.py:19-23](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/14_spider_save.py#L19)：

```python
for i in range(len(quotes)):
    quote_text = quotes[i].text
    author_text = authors[i].text
```

这个站点上两者都是 10 个，配对正确（实测 `quotes=10 authors=10 数量一致: True`）。**但只要有一条名言没有作者**（真实网站经常这样），`authors` 变成 9 个，`quotes[9]` 就 `IndexError`；反过来若 `authors` 更长，你会**悄悄把对应关系错位**——第 5 条名言配上第 4 个作者，而且完全不报错。

两种更安全的方法，都实测过：

```python
# 方法 A：zip 配对（quotes / authors 来自前面两次 find_all）
for i, (q, a) in enumerate(zip(quotes, authors), start=1):
    print(f"{i}. {a.text}: {q.text[:38]}")

# 方法 B：按「块」取 —— 最稳，天生配对
for i, block in enumerate(soup.select("div.quote"), start=1):
    text = block.select_one("span.text").text
    author = block.select_one("small.author").text
    print(f"{i}. {author} —— {text[:35]}")
```

方法 B 实测输出：

```text
1. Albert Einstein —— “The world as we have created it is
2. J.K. Rowling —— “It is our choices, Harry, that sho
```

但方法 A 有它自己的坑，我验证了 `zip` 在数量不等时**静默截断**：

```text
list(zip([1,2,3,4], ["a","b"]))  ->  [(1, 'a'), (2, 'b')]      # 后两条数据无声消失
```

> 📌 通用原则：**能按块取，就不要按列对齐。** 按列对齐等于把「两个列表长度相等」当成前提，而 HTML 不保证这一点。

### 补两步：翻页，以及一个我实测出的意外

真实跑了一遍翻页（本站共 100 条 / 10 页）：

```text
第 1 页抓了 10 条
第 2 页抓了 10 条
...
第 10 页抓了 10 条
第 11 页: 状态码 200, 块数 0 -> 停止
总条数: 100
作者前3: [('Albert Einstein', 10), ('J.K. Rowling', 9), ('Marilyn Monroe', 7)]
```

**注意第 11 页：状态码是 200，不是 404。** 服务器返回了一个「空页面」，HTTP 层面完全成功。所以：

> ⚠️ **`if status_code == 404: break` 单独用是不安全的**——这站会在第 11 页给你一个 200 空页，如果你的退出条件只看状态码，循环会一直抓到天荒地老（或者抓到内存爆）。**必须以「解析出的数据条数为 0」作为退出条件**：

```python
import requests
from bs4 import BeautifulSoup

HEADERS = {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
                         "AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36"}

page = 1
all_data = []
while True:
    url = f"http://quotes.toscrape.com/page/{page}/"
    r = requests.get(url, headers=HEADERS, timeout=10)
    if r.status_code != 200:
        print(f"第 {page} 页状态码 {r.status_code}，停止")
        break
    blocks = BeautifulSoup(r.text, "html.parser").select("div.quote")
    if not blocks:                       # ← 真正的结束条件
        print(f"第 {page} 页没有数据了，共抓到 {len(all_data)} 条")
        break
    for b in blocks:
        all_data.append([b.select_one("span.text").text,
                         b.select_one("small.author").text])
    print(f"第 {page} 页抓了 {len(blocks)} 条")
    page += 1
    if page > 50:                        # ← 保险丝：万一结构变了也不会死循环
        break
```

**两道保险**：数据条数为 0 退出 + 页数上限兜底。真实爬虫里，「看起来永远不会结束」的循环几乎都是因为只信了状态码。

顺带说明：`13_spider.py` 打印的 10 条**不是全站数量，只是第一页**。以后每次抓取都要主动问一句「我抓全了吗」。

## 四、`requests` + `BeautifulSoup` 最小必会集

```python
import requests
from bs4 import BeautifulSoup

URL = "http://quotes.toscrape.com/"
HEADERS = {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/120.0.0.0 Safari/537.36"}

r = requests.get(URL, headers=HEADERS, timeout=10, params={"page": 2})
r.status_code         # 200 / 404 / 403 ...
r.text                # HTML 源码字符串
r.content             # 字节（下载图片用这个）
r.raise_for_status()  # 非 2xx/3xx 直接抛 HTTPError，比手写 if 更全
r.request.headers     # 实际发出去的请求头 —— 用来验证 UA 有没有生效

soup = BeautifulSoup(r.text, "html.parser")      # 解析器写 html.parser 就够
soup.find("div")                      # 第一个匹配，找不到返回 None
soup.find_all("span", class_="text")  # 全部匹配，返回列表（空列表！不是 None）
soup.select("div.quote > small.author")   # CSS 选择器，支持后代/子选择
soup.select_one("span.text")              # CSS 取第一个，找不到返回 None
tag = soup.select_one("div.quote")
tag.text                               # 标签内的文字
tag.get("href")                        # 取属性，没有则 None
print(f"第 2 页状态码 {r.status_code}，本页 quote 块 {len(soup.select('div.quote'))} 个")
```

两个 `None` 陷阱：

- `find` / `select_one` 找不到返回 **`None`**，紧接着 `.text` 就是 `AttributeError: 'NoneType' object has no attribute 'text'`。
- `find_all` / `select` 找不到返回 **空列表 `[]`**，**不报错**——`for` 直接跳过，你会以为「网站没数据」。**抓完一定要打印 `len()`。**
