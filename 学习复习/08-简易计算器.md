## 1. `✅ 结果：2.5*4.0=10.00` —— 小数位数不一致

[19_calculator.py:37](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/19_calculator.py#L37)：

```python
record = f"{num1}+{num2}={result:.2f}"
```

`result` 有 `:.2f`，**`num1` 和 `num2` 没有**。它们是 `float()` 的产物，默认 `str()` 最短表示，整数输入一定带 `.0`。逐条实测：

| 输入 | `str(变量)` | `f"{变量:.2f}"` | 用户看到的完整行 |
|---|---|---|---|
| `2.5` | `2.5` | `2.50` | `2.5*4.0=10.00` |
| `10` | `10.0` | `10.00` | `10.0+0.0=10.00` |
| `1/3` | `0.3333333333333333` | `0.33` | `1.0/3.0=0.33` |
| `23.456` | `23.456` | `23.46` | `23.456+0.0=23.46` |

修法：三个数一起格式化。

```python
record = f"{num1:.2f} + {num2:.2f} = {result:.2f}"
print(f"✅ 结果：{record}")     # 打印和记录用同一个变量，就不会两处不一致
```

> **原则**：同一个信息只格式化一次，赋给变量，再到处用。你打印的和存盘的不是同一行字符串时，历史记录就对不上屏幕。

## 2. `:.2f` 是四舍五入吗？（实测：不一定是）

`1/3` → `0.33`，`23.456` → `23.46` 看起来都是四舍五入，但：

```python
v = 2.675
print(round(v, 2))     # 2.67
print(f"{v:.2f}")      # 2.67
print(format(v, ".20f"))   # 2.67499999999999982236
```

`2.675` 在二进制里存的是 `2.67499999...`（实测打印的就是这串），所以「四舍五入」得往下。这不是 bug，是浮点的本质：`.2f` 和 `round()` 用的是**银行家舍入**，且作用在**已经很接近**的十进制近似值上。

需要精确小数（钱、成绩统计）时用 `Decimal`，且必须传**字符串**：

```python
from decimal import Decimal, ROUND_HALF_UP
v = 2.675
print(Decimal(str(v)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))  # 2.68 ✅
print(Decimal(v).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))       # 2.67 ❌ 又用二进制值
```

实测两条分别是 `2.68` 和 `2.67`——**差别只在有没有 `str()`**。计算器用 `.2f` 够了，但如果哪天要统计绩点，这条必须记住。

## 3. 同样的代码写了 4 遍

四个函数唯一不同的就是运算符和那个符号，但 `load/save/格式化/存盘/打印/except` 抄了 4 次：

| 函数 | 行数 | 真正不同的部分 |
|---|---|---|
| `addition` | 14 | `+` |
| `subtraction` | 14 | `-` |
| `multiplication` | 14 | `*` |
| `divisionmethed` | 16 | `/` + `except ZeroDivisionError` |

改一处格式化，你得记着改四处——第 1 节那个不一致，就是这么来的。

[01-基础语法与流程控制.md](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/%E5%AD%A6%E4%B9%A0%E5%A4%8D%E4%B9%A0/01-%E5%9F%BA%E7%A1%80%E8%AF%AD%E6%B3%95%E4%B8%8E%E6%B5%81%E7%A8%8B%E6%8E%A7%E5%88%B6.md) 讲过的「变化的是数据，不变的是流程」，这里是标准答案：

```python
import operator

OPS = {
    "1": ("加法", operator.add, "+"),
    "2": ("减法", operator.sub, "-"),
    "3": ("乘法", operator.mul, "*"),
    "4": ("除法", operator.truediv, "/"),
}

def read_number(prompt):
    """拿到一个数字，或者 None。"""
    while True:
        text = input(prompt).strip()
        if text == "":
            print("❌ 请输入数字")
            continue
        try:
            return float(text)
        except ValueError:
            print(f"❌ '{text}' 不是有效数字！")

def calculate(choice):
    name, func, symbol = OPS[choice]
    print(f"--- 欢迎使用{name} ---")
    num1 = read_number("请输入第一个数字：")
    num2 = read_number("请输入第二个数字：")
    if num1 is None or num2 is None:
        return
    try:
        result = func(num1, num2)
    except ZeroDivisionError:
        print("❌ 数学老师警告：除数不能为 0！")
        return
    record = f"{num1:.2f} {symbol} {num2:.2f} = {result:.2f}"
    history.append(record)
    save_history()
    print(f"✅ 结果：{record}")
```

`operator.add` 是函数版的 `+`（`import operator`，标准库，不用装东西）。`OPS` 那张表还能顺手当菜单：

```python
for key, (name, _func, _sym) in OPS.items():
    print(f"{key}.{name}")
```

加个「取模」只要往 `OPS` 里塞一行 `"5": ("取模", operator.mod, "%")`，**不用写新函数**。

> ⚠️ **坑**：如果保留原来的 `if choice == "1"` 分支去调 `calculate()`，`OPS` 表和 `if` 链仍是两份真相。要么用表 + `OPS[choice]` 查（注意用 `if choice not in OPS` 先挡住，别 `KeyError`），要么继续用 `if` 链。**别一半新一半旧。**

## 4. `history` 这个名字：模块全局 + `global`

```python
history = []          # 模块级

def main():
    global history
    history = load_data()     # 重新绑定，必须 global
```

这里对，但脆。三个后果：

1. **单元测试要先重置全局**。见 [09-模块与单元测试.md](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/%E5%AD%A6%E4%B9%A0%E5%A4%8D%E4%B9%A0/09-%E6%A8%A1%E5%9D%97%E4%B8%8E%E5%8D%95%E5%85%83%E6%B5%8B%E8%AF%95.md)。
2. **`import` 就执行 `main()` 的风险**。你已经写了 `if __name__ == "__main__"`（[:122](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/19_calculator.py#L122)），这一条安全了。
3. 模块级 `history = []` 和 `main()` 里 `history = load_data()` 是**两个不同时刻的两个列表**，中间 `append` 的东西会跟着旧列表消失。实测：

```python
history = []
def add(x): history.append(x)     # 没有 global，append 仍然改的是模块那个列表
add("a")
history = ["b"]                    # 模块级重新绑定 → add() 下次改的又是新列表
print(history)                      # ['b']
```

在函数里改成 `history = history + [x]` 这种**赋值写法**（而不是 `append`），就必须 `global`，否则：

```python
def add_bad(x):
    try:
        history.append(x)
        history = history      # 只要函数里出现“给这个名字赋值”，history 立刻变局部
    except UnboundLocalError as e:
        return f"UnboundLocalError: {e}"
```

实测返回 `UnboundLocalError: cannot access local variable 'history' where it is not associated with a value`，而且**调用之后 `history` 一个元素都没进**。

干净写法是别藏全局：**函数收列表当参数、返回新状态**（通讯录 v4 已经这么干了）。

```python
def calculate(choice, history):
    ...
    history.append(record)
    return history, record
```

## 5. 除零和非法输入：这两个函数做对了

[:88](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/19_calculator.py#L88) 单独接了 `ZeroDivisionError`，实跑除法 `10 / 0`：

```
请输入第二个数字：❌ 数学老师警告：除数不能为 0！
```

输入 `abc`：

```
请输入第二个数字：❌ 输入的不是有效数字！
```

两条都优雅。**但另外三个函数没有除零分支**——加减乘本来就不会除零，所以没事。这个写法没问题，只是注意：

- **`float("abc")` 报 `ValueError`，`float("")` 也报 `ValueError`**：

```
ValueError: could not convert string to float: 'abc'
ValueError: could not convert string to float: ''
```

两条消息不同，你的 `except ValueError` 不分细节，所以都能挡住。但直接回车时屏幕上只看到一句「不是有效数字」，用户容易以为自己没输入成功——第 7 节那个循环会重问，比现在只问一次更好。

- ⚠️ **一个例外：空输入时第二个 `input()` 根本不会执行**，于是后面那条输入会顶到菜单上，整条输入流错位一格。实测（`1`→`abc`→`9`→`9`→`5`）：

```
--- 欢迎使用加法 ---
请输入第一个数字：❌ 输入的不是有效数字！
1.加法
...
请选择：退出计算器，再见！
```

第一个数字报错后函数直接结束，**`9 9 5` 里的 `9` 被当成了菜单选择**（无效选择、再无效选择），最后 `5` 退出——原本要算的那一步整段消失。第 7 节的 `read_number` 循环把「重问」关在函数里，就不会错位。

## 6. 用字符串比菜单，不用 `int` —— 这个选择是对的

[:104](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/19_calculator.py#L104) `choice = input("请选择：").strip()`，然后 `if choice == "1"`。通讯录 v1-v3 用 `int()` + `isdigit()`，你这里直接比字符串——**省掉一整类 `ValueError`**。建议保持，或者 `if choice not in OPS: continue` 更短（见第 3 节）。

⚠️ 别写成 `if choice not in "123456"`：`"12" not in "123456"` 实测是 `False`（子串匹配），两位数是非法选择却会被放过。用集合或列表：`if choice not in {"1", "2", "3", "4", "5", "6"}`。

## 7. 历史记录的问题

`show_history`（[:23](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/19_calculator.py#L23)）：

```python
for item in history:
    print(item)
```

三个具体问题，都在通讯录文档里出现过：

1. **没有编号**。列表打印出来和一堆散行没区别，想引用第 5 条只能手数。用 `enumerate(history, start=1)`（[03 号文档](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/%E5%AD%A6%E4%B9%A0%E5%A4%8D%E4%B9%A0/03-%E5%B0%8F%E6%B8%B8%E6%88%8F%E4%B8%8E%E9%9A%8F%E6%9C%BA%E9%80%BB%E8%BE%91.md) 讲过 `start=1`）。
2. **没有上限**。跑一整天文件就无限长，而且每次算完都**全量重写整个文件**（`json.dump(history)`）。1 万条时每次加法都要写 1 万条。
3. **没有清空/删除**。只能一直加。

顺手能加的：

```python
def show_history():
    if not history:
        print("暂无历史记录")
        return
    print(f"--- 共 {len(history)} 条 ---")
    for i, item in enumerate(history, start=1):
        print(f"{i}. {item}")

MAX_HISTORY = 50          # 只留最近 50 条，实测 5 条时留 3 条、30 条时留 20 条
...
history = history[-MAX_HISTORY:]
save_history()
```

`history[-MAX:]` 是「最后 MAX 个」，`len` 不够时不会报错（切片不越界）。

## 8. ⚠️ 记进历史的时机：算完了才记

这条第 5 节其实已经做对了，但值得单列，因为它和通讯录 v4 的错误相反：

```python
result = num1 / num2          # ← 可能在这里炸

record = f"{num1}/{num2}={result:.2f}"
history.append(record)
save_history()
```

先算、后 append——如果顺序反过来，除零时历史里会留下一条 `10.0/0.0=` 的**垃圾记录**。

更完整的写法是把「算式」和「记录」绑成一个动作，出错就**显式不记**。可复制版：

```python
def do_op(a, b, func, history):
    """先算，算成功才记录。返回 (是否成功, 给屏幕看的那句话)。"""
    try:
        result = func(a, b)
    except ZeroDivisionError:
        return False, "❌ 数学老师警告：除数不能为 0！"
    except Exception as e:
        return False, f"❌ 算不出来：{type(e).__name__}: {e}"
    record = f"{a:.2f} = {result:.2f}"
    history.append(record)
    return True, f"✅ {record}"

h = []
ok, msg = do_op(6, 3, lambda a, b: a / b, h)
print(ok, "|", msg, "| history =", h)
ok, msg = do_op(6, 0, lambda a, b: a / b, h)
print(ok, "|", msg, "| history =", h)
```

实测（`⏎` 是换行）：

```
True | ✅ 6.00 = 2.00 | history = ['6.00 = 2.00']⏎False | ❌ 数学老师警告：除数不能为 0！ | history = ['6.00 = 2.00']
```

除零那次 `history` 没变——**失败的运算不该留下记录**。

> ⚠️ 别顺手加「失败也记录一行」的 `else` 分支，那不是历史记录，是错误日志——两件事，存两个地方。

## 9. 文件名拼错：`history_calcilator.json`

[:5](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/19_calculator.py#L5) `file_name = "history_calcilator.json"`——`calcilator` 应为 `calculator`。还有 `divisionmethed`（`methed` 应为 `method`）。

这类拼错**不会报错**，只会静默生成一个名字错的文件，等你哪天改对了拼写，旧历史就「凭空消失」。而且你的函数名 `load_data`/`save_history` 一个像读、一个像写，`file_name` 又是模块级——三个信号叠在一起，半年后你自己也找不到数据在哪。

> **规则**：数据文件名只出现一次（一个常量），并且**改它等于迁移动作**，得有意识地做（改名前先复制一份旧文件）。通讯录 v4 用的是 `FILE_NAME` 常量，和你这里一样——这点你是对的。

## 10. 练手：直接支持的输入

**① 一次输入多个数**

```python
text = input("请输入两个数字（空格隔开）：")
parts = text.split()
if len(parts) != 2:
    print("❌ 请输入两个数字")
else:
    a, b = parts
    ...
```

坑：`"  ".join` / 连续空格 → `split()` 不带参数会自动吃掉连续空白（实测 `len("1  2".split())` 是 `2`，而 `split(" ")` 是 `3`）。要让用户可以用逗号，先 `text.replace(",", " ")`。

⚠️ 还有一个真实的错位坑：`a, b = "1 2 3".split()` 直接 `ValueError: too many values to unpack`。所以**必须先查 `len`，再解包**。这个报错很直白，但它是在你以为校验过了之后才炸的。

**② 表达式计算器**：让用户输入 `2+3*4`，算出答案。

`eval` 能一行做完，但**别用**：用户输入 `__import__('os').system('del /q *')` 就真的执行了。正经做法：

1. **只支持两个操作数一种情况**：正则切成「数字 运算符 数字」三段，自己查表算：

```python
import re
m = re.fullmatch(r"\s*(-?\d+(?:\.\d+)?)\s*([+\-*/])\s*(-?\d+(?:\.\d+)?)\s*", "3.5 + 2")
if m:
    a, op, b = m.group(1), m.group(2), m.group(3)
    print(float(a) + float(b))     # 按 op 查 OPS
```

2. **要支持优先级**（`2+3*4`）：用标准库 `ast` 白名单遍历，只允许 `BinOp/UnaryOp/Add/Sub/Mult/Div`，遇到别的节点直接报错。它比手写解析器短得多，而且比 `eval` 安全。

> 上面这段的实测结果：`3.5 + 2` → `5.5`；`2+3*4` → **`14`**。优先级是**自然算对的**——因为 `3.5 + 2` 这个正则解析器只支持「两段操作数」，`2+3*4` 根本匹配不上，会落到「看不懂」分支。**这就是这类计算器最容易骗人的地方**：你以为它「按优先级算错了」，其实它是**没解析成功**却给了你一个数。
>
> 要正确算 `2+3*4`，用 `ast`。下面这段可以整块复制运行：

```python
import ast
import operator

BINOPS = {ast.Add: operator.add, ast.Sub: operator.sub,
          ast.Mult: operator.mul, ast.Div: operator.truediv,
          ast.Mod: operator.mod, ast.Pow: operator.pow}
UNARYOPS = {ast.USub: operator.neg, ast.UAdd: operator.pos}

def safe_eval(expr):
    """只算加减乘除幂取模和一元正负，别的（名字、函数调用、下标）一律拒绝。"""
    node = ast.parse(expr, mode="eval").body
    if isinstance(node, ast.Constant) and isinstance(node.value, (int, float)):
        return node.value
    if isinstance(node, ast.BinOp) and type(node.op) in BINOPS:
        return BINOPS[type(node.op)](safe_eval(ast.unparse(node.left)),
                                     safe_eval(ast.unparse(node.right)))
    if isinstance(node, ast.UnaryOp) and type(node.op) in UNARYOPS:
        return UNARYOPS[type(node.op)](safe_eval(ast.unparse(node.operand)))
    raise ValueError(f"不支持的表达式：{ast.unparse(node)!r}")

for e in ["2+3*4", "(2+3)*4", "2**10", "-5+3", "10%3", "1/0", "__import__('os')"]:
    try:
        print(f"{e:<18} = {safe_eval(e)}")
    except ZeroDivisionError:
        print(f"{e:<18} -> ZeroDivisionError")
    except (ValueError, SyntaxError) as ex:
        print(f"{e:<18} -> {type(ex).__name__}: {str(ex)[:36]}")
```

实测（Python 3.15.0）：

```
2+3*4              = 14
(2+3)*4            = 20
2**10              = 1024
-5+3               = -2
10%3               = 1
1/0                -> ZeroDivisionError
__import__('os')   -> ValueError: 不支持的表达式："__import__('os')"
```

优先级全对（`2+3*4=14`，不是 `20`），`1/0` 会抛出可捕获的 `ZeroDivisionError`，函数调用被挡住。但注意 `2**999999999` 这种会算到天荒地老，真要做得加数字长度和操作次数上限。**所以这仍然只是玩具**，只是不会像 `eval` 那样把整台电脑交出去。
