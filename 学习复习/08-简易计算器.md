## 二、`.2f` 只作用在结果上，操作数还是原样

[19_calculator.py:37](../19_calculator.py#L37) 和 [:41](../19_calculator.py#L41)：

```python
record = f"{num1}+{num2}={result:.2f}"
print(f"✅ 结果：{num1}+{num2}={result:.2f}")
```

`result` 保留两位，但 `num1` / `num2` 是 `float` 的默认字符串。实测：

```text
f"{2.5}"      -> '2.5'
f"{2.5:.2f}"  -> '2.50'
f"{4.0}"      -> '4.0'        # 用户输入 4，显示成 4.0
f"{4.0:.2f}"  -> '4.00'
```

所以同一条记录里出现「2.5+4.0=6.50」：左边一位小数、右边两位。不是计算错，是**格式只加在了一处**。

两种统一方式，选一种并全篇贯彻：

```python
# A. 全用两位
f"{num1:.2f}+{num2:.2f}={result:.2f}"     # 2.50+4.00=6.50

# B. 操作数去掉无意义的 .0，结果保留两位
f"{num1:g}+{num2:g}={result:.2f}"         # 2.5+4=6.50
```

`g` 会按需要选择定点/科学计数法，并去掉尾随的 0。计算器面向人看，B 更自然。

## 三、`.2f` 不总是「四舍五入」

实测：

```text
2.675       原样=2.675                 .2f=2.67    round(2.675, 2)=2.67
0.1+0.2     原样=0.30000000000000004   .2f=0.30    round(..., 2)=0.3
```

`2.675` 在二进制里并不精确等于 2.675：

```text
Decimal(2.675) = 2.67499999999999982236431605997495353221893310546875
```

它比 2.675 小一点点，所以按「最近的可表示值」舍入得到 2.67。想让十进制人类规则生效，要用 `Decimal` 并从**字符串**构造：

```python
from decimal import Decimal
Decimal(str(2.675)).quantize(Decimal("0.01"))   # 2.68
```

计算器这种场景，`.2f` 足够；但涉及金额、对账时，不能在 `float` 上直接 `round`。

## 四、同一段代码写了四遍

四个函数 [19_calculator.py:30-89](../19_calculator.py#L30-L89) 的差别只有三处：提示语、运算符、实际运算。其余（两次 `float(input())`、拼 record、append、save、print）一字不差。

这带来三个具体成本：

1. 改一次格式要改四处，漏一处就出现第二节那种不一致。
2. 加一种运算（取余、乘方）要复制 14 行。
3. 修一个 bug（比如 `nan` 校验）要记得修四遍。

用表驱动压成一个函数：

```python
import operator

OPS = {
    "1": ("+", operator.add),
    "2": ("-", operator.sub),
    "3": ("*", operator.mul),
    "4": ("/", operator.truediv),
}

def calculate(choice):
    symbol, func = OPS[choice]
    a = ask_number("请输入第一个数字：")
    b = ask_number("请输入第二个数字：")
    result = func(a, b)
    record = f"{a:g}{symbol}{b:g}={result:.2f}"
    history.append(record)
    save_history()
    print(f"结果：{record}")
```

加一种运算只改 `OPS` 一行；格式只在一处；`ZeroDivisionError` 由 `truediv` 自己抛，`main` 统一接。实测输出见第五节。

## 五、`history`：模块全局 + `global` 的边界

[19_calculator.py:6](../19_calculator.py#L6) 建了模块级列表：

```python
history = []
```

[19_calculator.py:92-94](../19_calculator.py#L92-L94)：

```python
def main():
    global history
    history = load_data()
```

两件事要分清：

| 操作 | 需要 `global` 吗 | 原因 |
| --- | --- | --- |
| `history.append(record)` | 不需要 | 修改列表**内容**，没有重新绑定名字 |
| `history = load_data()` | 需要 | 让 `history` 指向一个新列表，是重新绑定 |

如果 `main` 里漏写 `global history`，`history = load_data()` 会创建一个**局部**变量；四个运算函数仍然往模块级的空列表里 append，`save_history()` 写的也是空列表——历史永远存不下来，而且不报错。

更好的写法是让 `main` 持有列表、把列表作为参数传下去，彻底不用 `global`。对当前规模，`global` 可以接受，但要知道它的边界。

## 六、除零和非法输入：做对了两件事，漏了一件

做对的：

- [19_calculator.py:86-87](../19_calculator.py#L86-L87) 捕获 `ValueError`，非数字不会崩。
- [19_calculator.py:88-89](../19_calculator.py#L88-L89) 捕获 `ZeroDivisionError`，除零有友好提示。

漏掉的：**第一个数字非法时，第二个数字不会被读取**。实测输入 `1, abc, 2, 7, 3, 5`：

```text
请选择：--- 欢迎使用加法 ---
请输入第一个数字：❌ 输入的不是有效数字！
请选择：--- 欢迎使用减法 ---
请输入第一个数字：请输入第二个数字：✅ 结果：7.0-3.0=4.00
```

`abc` 在 `num1` 处失败，函数直接返回，`num2` 那行根本没执行。用户本来想输入的 `2`（作为第二个操作数）被菜单读走，启动了减法；`7` 和 `3` 成了减法的两个操作数。**输入流错位**，而且每一步看起来都「正常」。

修法不是加一个 `try`，而是把「读一个合法数字」抽成一个会重试或明确失败的函数，并让失败路径**不消耗后续输入**的假设成立：

```python
def ask_number(prompt):
    text = input(prompt).strip()
    try:
        value = float(text)
    except ValueError:
        raise ValueError(f"不是有效数字：{text!r}") from None
    if not math.isfinite(value):
        raise ValueError(f"必须是有限数：{text!r}")
    return value
```

`main` 捕获后回到菜单，用户重新选运算、重新输入两个数。语义清楚：一次运算要么完整成功，要么整次作废。

## 七、历史记录的时机：算完才记

[19_calculator.py:38-39](../19_calculator.py#L38-L39) 的顺序是：

```python
history.append(record)
save_history()
print(...)
```

先算、后记、再打印。实测「第二个数字非法」的场景（输入 `1, 2.5, abc, 6, 5`）：

```text
请选择：暂无历史记录
请选择：退出计算器，再见！
文件是否存在: No such file or directory
```

失败的那次没有留下任何记录，`history_calcilator.json` 甚至没被创建。这是正确的：**历史只记录成功完成的运算**。

如果反过来先 append 再计算，失败也会留下一条 `2.5+abc=...` 的脏数据。顺序本身就是一致性保证。

## 八、`float("nan")` 能通过所有检查

实测输入 `nan` 和 `1`：

```text
✅ 结果：nan+1.0=nan
```

`float("nan")` 不抛异常，`nan + 1` 也不抛异常，`.2f` 把它格式化成 `nan`。同理 `inf`：

```text
float("inf") + 1 -> inf
```

修法是在 `ask_number` 里加 `math.isfinite` 检查（见上一节）。这条和 07 号文档的 `-10` 是同一类：**语法合法 ≠ 业务有效**。

另外，`float("1e309")` 会得到 `inf`，同样被 `isfinite` 挡住。

## 九、两个拼写错误，程序都不会提醒

| 位置 | 写的 | 应为 | 后果 |
| --- | --- | --- | --- |
| [19_calculator.py:5](../19_calculator.py#L5) | `history_calcilator.json` | `history_calculator.json` | 文件名永久带错字；以后按正确名字找文件会找不到 |
| [19_calculator.py:74](../19_calculator.py#L74) | `divisionmethed` | `divide` 或 `division_method` | 方法名带错字；搜索 `division` 找不到它 |

两处都属于「字符串当标识符」：程序照跑，只有人受影响。文件名尤其麻烦——它已经写进了现有数据文件，改名要同时迁移旧文件：

```python
OLD, NEW = "history_calcilator.json", "history_calculator.json"
if os.path.exists(OLD) and not os.path.exists(NEW):
    os.replace(OLD, NEW)
```

改完用 `ls` 和 `grep` 各确认一次，别只跑程序看它没崩。

## 十、其他值得改的点

| 点 | 现状 | 建议 |
| --- | --- | --- |
| 历史无限增长 | 每次成功都 append | 只保留最近 N 条（如 `history = history[-50:]`） |
| 历史无编号 | `show_history` 直接打印字符串 | `enumerate(history, start=1)`，见修正版 |
| 每次重写整个文件 | `save_history` 全量 `json.dump` | 记录少时可以接受；上千条再考虑追加写或 SQLite |
| 读取失败静默 | `load_data` 返回 `[]` | 至少打印一行提示，否则用户以为历史丢了 |
| 菜单用字符串比较 | `choice == "1"` | 正确；不要 `int(input())`，否则非数字直接崩 |
| 输入没去空格 | `input(...).strip()` 已写 | 保留；`float` 本身也能处理空格，但统一去空格更稳 |

## 十一、修正版（完整可运行，已实测）

```python
import json
import math
import operator
import os

FILE_NAME = "history_calculator.json"
OPS = {
    "1": ("+", operator.add),
    "2": ("-", operator.sub),
    "3": ("*", operator.mul),
    "4": ("/", operator.truediv),
}
history = []


def load_history():
    if not os.path.exists(FILE_NAME):
        return []
    try:
        with open(FILE_NAME, encoding="utf-8") as f:
            data = json.load(f)
    except (json.JSONDecodeError, OSError):
        return []
    return data if isinstance(data, list) else []


def save_history():
    with open(FILE_NAME, "w", encoding="utf-8") as f:
        json.dump(history, f, ensure_ascii=False, indent=4)


def ask_number(prompt):
    text = input(prompt).strip()
    try:
        value = float(text)
    except ValueError:
        raise ValueError(f"不是有效数字：{text!r}") from None
    if not math.isfinite(value):
        raise ValueError(f"必须是有限数：{text!r}")
    return value


def calculate(choice):
    symbol, func = OPS[choice]
    a = ask_number("请输入第一个数字：")
    b = ask_number("请输入第二个数字：")
    result = func(a, b)
    record = f"{a:g}{symbol}{b:g}={result:.2f}"
    history.append(record)
    save_history()
    print(f"结果：{record}")
    return record


def show_history():
    if not history:
        print("暂无历史记录")
        return
    for index, item in enumerate(history, start=1):
        print(f"{index}. {item}")


def main():
    global history
    history = load_history()
    while True:
        print("\n1.加法  2.减法  3.乘法  4.除法  5.退出  6.历史")
        choice = input("请选择：").strip()
        if choice == "5":
            break
        if choice == "6":
            show_history()
            continue
        if choice not in OPS:
            print("无效的选择")
            continue
        try:
            calculate(choice)
        except ValueError as exc:
            print("输入错误：", exc)
        except ZeroDivisionError:
            print("数学错误：除数不能为 0")


if __name__ == "__main__":
    main()
```

实测输入 `1, 2.5, 4, 4, 10, 0, 3, nan, 1, 6, 5, 6, 5`：

```text
结果：2.5+4=6.50
数学错误：除数不能为 0
输入错误： 必须是有限数：'nan'
结果：6+5=11.00
1. 2.5+4=6.50
2. 6+5=11.00
```

落盘内容：

```json
[
    "2.5+4=6.50",
    "6+5=11.00"
]
```

一次修掉：四段重复、格式不统一、`nan` 漏网、历史无编号、失败记录不落盘、文件名/函数名拼错。

## 十二、错题清单

| 现象 | 根因 | 对策 |
| --- | --- | --- |
| `2.5+4.0=6.50` | 格式只加在结果上 | 操作数和结果统一格式 |
| `2.675 -> 2.67` | 二进制无法精确表示，`float` 舍入 | 金额用 `Decimal(str(x))` |
| 四段代码几乎一样 | 复制粘贴 | `OPS` 表 + 一个 `calculate` |
| `nan+1.0=nan` | 只捕获异常，没校验有限性 | `math.isfinite` |
| 第一个数非法后输入错位 | 失败路径提前返回，后续输入没人消费 | 一次运算整体成功/失败，回菜单重来 |
| 历史文件找不到 | `calcilator` 拼错 | 改名并迁移旧文件 |
| 函数搜不到 | `divisionmethed` 拼错 | 改名为 `divide` |
| 历史无限增长 | 没有上限 | `history = history[-50:]` |
