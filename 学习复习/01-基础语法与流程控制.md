## 一、average-01.py —— 同一件事写了两遍

这个文件上下两段是两道题：`L5-18` 是原始版，`L20-35` 是重构版。**直接运行会先问 5 个成绩，再问 3 个成绩**，一共 8 次输入。

### 原始版：提示语从「第 0 个」开始

[average-01.py:7-9](../average-01.py#L7-L9)：

```python
for i in range(5):
    s = int(input(f"请输入第{i}个成绩："))
    scores.append(s)
```

实际输出（喂入 85 92 78 60 99）：

```text
请输入第0个成绩：请输入第1个成绩：请输入第2个成绩：请输入第3个成绩：请输入第4个成绩：所有成绩：[85, 92, 78, 60, 99]
总分是414，平均分是82.8
```

四处可改进：

| 问题 | 位置 | 说明 |
| --- | --- | --- |
| 人类没有「第 0 个」 | `:8` | 循环变量从 0 起，展示要用 `i + 1` |
| `int(input())` 裸奔 | `:8` | 输入 `abc` 直接 `ValueError` |
| 手写累加循环 | `:11-13` | `sum(scores)` 一行替代 |
| 重复输入同一批数据 | `:20-35` | 学习可以，交付代码里应只留一份 |

### 重构版：三层输入校验

[average-01.py:21-32](../average-01.py#L21-L32)：

```python
scores = []
while len(scores) < 3:
    text = input(f"请输入第{len(scores) + 1}个成绩：").strip()
    try:
        s = int(text)
    except ValueError:
        print("必须时整数，重来")
        continue
    if not 0 <= s <= 100:
        print("成绩要在0~100之间")
        continue
    scores.append(s)
```

实际输出（喂入 90 / abc / 200 / 85 / 77）：

```text
请输入第1个成绩：请输入第2个成绩：必须时整数，重来
请输入第2个成绩：成绩要在0~100之间
请输入第2个成绩：请输入第3个成绩：所有成绩：[90, 85, 77]
总分是252,平均分是84.0
```

注意第 2、3 行：**`continue` 之后 `len(scores)` 没变，提示语仍然是「第 2 个」**。这就是用 `len(scores) + 1` 而不是循环变量 `i` 的好处——失败的那次输入不会被算进进度。

同时注意这里的 `try` **只包住 `int(text)`**，没有把后面的范围判断也包进去。这是对的：范围不合法不是异常，是业务规则，用 `if` 表达更清楚。

> ⚠️ 文案 typo：「必须**时**整数」应为「必须**是**整数」。这类错误程序不会报，只能靠读输出发现。
> ⚠️ 两段的 `print` 一个用全角逗号、一个用半角逗号（`总分是252,平均分`），也是复制改写时留下的不一致。

### 为什么平均分是 84.0 而不是 84

`sum(scores) / len(scores)` 在 Python 3 里**永远是浮点除法**，即使能整除也返回 `float`。想显示成 `84` 用 `{avg:g}`，想固定一位小数用 `{avg:.1f}`。

## 二、list-01.py —— 索引、追加、遍历

[list-01.py:1-5](../list-01.py#L1-L5)：

```python
scores = [85, 92, 78, 60, 99]
names = ["张三", "李四", "王五"]
print(scores[1])       # 92，索引从 0 开始
scores.append(100)     # 长度变 6
print(len(scores))     # 6
```

实际输出：

```text
92
6
```

录入名单段 [list-01.py:10-13](../list-01.py#L10-L13)：

```python
for i in range(3):
    new_name = input(f"请输入第{i + 1}个同学姓名：").strip()
    if new_name:
        classnames.append(new_name)
```

实际输出（喂入 张三 / 李四 / 王五）：

```text
请输入第1个同学姓名：请输入第2个同学姓名：请输入第3个同学姓名：
全班同学名单如下：
同学：张三
同学：李四
同学：王五
全班一共录入了3位同学。
```

**做对的地方**：`i + 1`、`.strip()`、`if new_name`（空输入或纯空格不追加）。

**要留意的语义**：`range(3)` 是「问 3 次」，不是「收 3 个人」。如果三次里有空格，最后只会录入 2 人，但提示语不会补问。想让「收满 3 人才停」：

```python
names = []
while len(names) < 3:
    name = input(f"请输入第{len(names) + 1}个同学姓名：").strip()
    if not name:
        print("姓名不能为空")
        continue
    names.append(name)
```

这正好和 `average-01.py` 重构版的写法一致。

## 三、loop-01.py —— 一个恒真条件，和一次正确的重写

### 注释里的错误版本

[loop-01.py:1-10](../loop-01.py#L1-L10) 保留了旧写法：

```python
if score > 100 or score < 0:
```

注释里已经标了「错误写法 `score < 100 or score < 0`」。实测这两个条件的真假：

```text
score<100 or score<0 对 150: False
score<100 or score<0 对 -10: True
```

`score < 100 or score < 0` 对 -10 是 True，看起来能挡住负数；但对 150 却是 False，超上限被放过。**`or` 只要一边成立就整体成立，它表达不了「同时越界」**。正确写法是 `or` 连接两个「越界」条件：

```python
if score < 0 or score > 100:    # 小于 0 或 大于 100
```

### 当前版本

[loop-01.py:12-23](../loop-01.py#L12-L23)：

```python
while True:
    text = input("请输入成绩（输入 q 退出）：").strip()
    if text.lower() == "q":
        break
    if not text.isdigit():
        print("请输入数字")
        continue
    score = int(text)
    if score < 0 or score > 100:
        print("成绩必须在 0~100 之间")
        continue
    print(f"{score}分，" + ("合格" if score >= 60 else "不合格"))
```

实际输出（喂入 abc / 150 / 85 / q）：

```text
请输入成绩（输入 q 退出）：请输入数字
请输入成绩（输入 q 退出）：成绩必须在 0~100 之间
请输入成绩（输入 q 退出）：85分，合格
请输入成绩（输入 q 退出）：
```

这版结构已经完整：**退出 → 类型 → 范围 → 业务**。

`isdigit()` 的边界要记住：

```text
'85'    -> True
'-5'    -> False      # 负号不算数字
'3.5'   -> False      # 小数点不算
' 85 '  -> False      # 空格不算（所以 input 后先 strip）
```

所以 `isdigit()` 适合「非负整数」；要允许负数或小数，就得改用 `int()`/`float()` + `try`。

## 四、count-01.py —— 有上限的循环写对了，无上限的循环写崩了

### 前半段：5 次机会

[count-01.py:1-15](../count-01.py#L1-L15)：

```python
count = 0
while count < 5:
    name = input("请输入你的名字（提示：姓谷）：")
    if name == "谷明真":
        print("欢迎回家！游戏结束。")
        break
    else:
        count += 1
        print(f"不认识你！你还有 {5 - count} 次机会。")

if count == 5:
    print("尝试次数太多，账号已锁定！")
```

实际输出（5 个错误名 + 正确名）：

```text
请输入你的名字（提示：姓谷）：不认识你！你还有 4 次机会。
...
请输入你的名字（提示：姓谷）：不认识你！你还有 0 次机会。

尝试次数太多，账号已锁定！
请输入你的名字（提示：姓谷）：欢迎回家！游戏结束
```

注意 `while count < 5` 退出时 `count == 5`，所以锁定分支能命中。这是「循环条件 + 循环后判断」的标准配合。

### 后半段：没有计数器

[count-01.py:17-24](../count-01.py#L17-L24)：

```python
while True:
    name = input("请输入你的名字（提示：姓谷）：").strip()
    if name == "谷明真":
        print("欢迎回家！游戏结束")
        break
    else:
        print("不认识你，请重新输入！\n")
```

这段**没有次数上限**，只有输入正确才退出；如果一直输错，程序永远不会停。前半段已经写对了，后半段却退回 `while True`，属于「同一文件里两套标准」。

另外缩进用了 3 个空格（`L18` 起），PEP 8 要求 4 个。Python 只要求同一块内一致，所以能跑，但和文件前半段视觉不一致。

## 六、check_age.py —— `assert` 是自检，不是用户校验

[check_age.py:1-7](../check_age.py#L1-L7)：

```python
def check_age(age):
    return "已成年" if age >= 18 else "未成年"

assert check_age(18) == "已成年"
assert check_age(17) == "未成年"

print("全部通过")
```

实际输出：`全部通过`。

两个要点：

1. **三元表达式**读法：`A if 条件 else B`，先看中间的条件，再看两边。
2. **`assert` 会在 `python -O` 下被整句删除**。实测：

```text
正常运行：断言通过
python -O：断言行被删除，仍然打印
```

所以 `assert` 只能用来「确认代码自己没写错」，**不能用来检查用户输入**。要拦截坏输入必须 `raise`（见 07 篇）。

## 七、把六个文件串成一套输入模板

所有交互脚本的骨架都可以收敛成这三层：

```python
while True:
    text = input("...（q 退出）：").strip()

    if text.lower() == "q":          # 1. 退出
        break
    try:
        value = int(text)            # 2. 转类型
    except ValueError:
        print("请输入整数")
        continue
    if not 0 <= value <= 100:        # 3. 判范围（业务规则）
        print("必须在 0~100")
        continue

    print(f"收到 {value}")           # 4. 正常业务
```

对照本类：

| 文件 | 退出 | 转类型 | 判范围 | 缺哪层 |
| --- | --- | --- | --- | --- |
| average-01（前） | ✗ | ✗ | ✗ | 全缺 |
| average-01（后） | ✗ | ✓ | ✓ | 退出 |
| loop-01 | ✓ | ✓ | ✓ | 无 |
| count-01（前） | 无退出选项 | — | — | 符合题意 |
| count-01（后） | ✗ | — | — | 无上限 |
| password_01 | ✗ | — | — | 无上限 |

| # | 现场 | 类型 | 对策 |

| 1 | `请输入第0个成绩` | 展示 bug | 循环变量 `i` 与人类序号 `i+1` 分开 |
