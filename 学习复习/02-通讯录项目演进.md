## 一、v1 `dictionary-01.py`：字典能用了，但只活在内存里

### 实际运行

输入序列：`1 → 张三 → 13800000000 → 2 → 3`

```text
欢迎使用简易通讯录！

--- 菜单 ---
1.添加联系人
2.查看所有联系人
3.退出
请选择操作（输入1/2/3）：请输入联系人姓名：请输入联系人电话：✅已保存：张三的电话时13800000000

--- 菜单 ---
...
请选择操作（输入1/2/3）：--- 联系人列表 ---
姓名：张三,电话：13800000000
...
请选择操作（输入1/2/3）：退出程序，再见！
```

### 这一版做对的

- 用 `dict` 存「姓名 → 电话」，`name in contacts` 判重（[dictionary-01.py:17](../dictionary-01.py#L17)），O(1) 查找。
- 空通讯录用 `len(contacts) == 0` 判断（[:28](../dictionary-01.py#L28)），能用；更 Python 的写法是 `if not contacts:`。
- 菜单用字符串比较（`choice == "1"`），不需要 `int()`，非法输入不会崩。

### 三个问题

1. **不存盘**：退出即清空。程序里没有任何 `open()`。
2. **不能删**：只有 1/2/3 三个选项。
3. **没有输入清洗**：`name = input(...)` 没 `.strip()`，`"张三 "` 和 `"张三"` 会被当成两个人（[:15](../dictionary-01.py#L15)、[:20](../dictionary-01.py#L20)）。
4. 文案 typo：「电话**时**138…」应为「电话**是**」（[:22](../dictionary-01.py#L22)）。不报错，只能靠读输出发现。

## 二、v2 `06_function_contacts.py`：从「一坨」拆成四个函数

### 结构变化

| 函数 | 职责 | 位置 |
| --- | --- | --- |
| `add_contacts()` | 问姓名/电话，判重后写入 | [:3-10](../06_function_contacts.py#L3-L10) |
| `show_contacts()` | 空则提示，否则逐条打印 | [:12-18](../06_function_contacts.py#L12-L18) |
| `delete_contacts()` | 列编号 → 读编号 → 校验 → 删除 | [:20-43](../06_function_contacts.py#L20-L43) |
| `main()` | 菜单循环，只负责分发 | [:46-67](../06_function_contacts.py#L46-L67) |

`contacts` 仍是模块级全局字典（[:1](../06_function_contacts.py#L1)），函数直接读写它。这是「能拆函数」的第一步，但还不是可测试的写法。

### 删除功能写得最完整

[06_function_contacts.py:25-43](../06_function_contacts.py#L25-L43)：

```python
names = list(contacts.keys())
for index, name in enumerate(names, start=1):
    print(f"{index}.{name}")

choice = input("请输入要删除的编号：").strip()
if not choice.isdigit():
    print("请输入有效数字！")
    return
number = int(choice)
if not 1 <= number <= len(names):
    print("输入的编号超出范围了！")
    return
target_name = names[number - 1]
del contacts[target_name]
```

三层校验齐全：**非数字 → 越界 → 执行删除**。`enumerate(..., start=1)` 直接给出人类编号，比 `range(len(names))` 清爽。

### 实际运行（显示 v2 的真实缺口）

输入：`1 → 张三 → 138… → 1 → 张三 → 139… → 2 → 3 → 9 → 4`

```text
请选择操作(输入1/2/3/4):请输入联系人姓名：请输入联系人电话：✅已保存：张三，电话：13800000000
请选择操作(输入1/2/3/4):请输入联系人姓名：⚠️ 你添加的张三已经存在了！
请选择操作(输入1/2/3/4):❌无效的选择！
请选择操作(输入1/2/3/4):--- 联系人列表 ---
姓名：张三，电话：13800000000
请选择操作(输入1/2/3/4):---请选择要删除的联系人编号：---
1.张三
请输入要删除的编号：输入的编号超出范围了！
```

注意那句 `❌无效的选择！`：重名分支**不会再读电话**（[:5-6](../06_function_contacts.py#L5-L6)），所以我喂进去的 `13900000000` 没有被 `add_contacts` 消费，而是被下一轮菜单当成选项读了，才出现「无效选择」。这正好说明：**交互脚本的输入流是按顺序消费的，一个分支少读一行，后面的输入就会整体错位**。

### 仍然存在的三个问题

1. **不存盘**（和 v1 一样）。
2. **菜单选择没有 `.strip()`**（[:55](../06_function_contacts.py#L55)），输入 `" 1"` 会走到 `else`。
3. **判重后电话被吞**：重名时只提示已存在，不再问电话（[:5-6](../06_function_contacts.py#L5-L6)），这是合理设计，但要在文档里写清。

## 三、v3 `07_file_test.py`：终于能存盘了

### 读取：三层防御

[07_file_test.py:6-18](../07_file_test.py#L6-L18)：

```python
def load_data():
    if not os.path.exists(FILE_NAME):
        return {}
    try:
        with open(FILE_NAME, "r", encoding="utf-8") as f:
            data = json.load(f)
    except (json.JSONDecodeError, OSError):
        print("通讯录文件损坏或无法读取，已按空通讯录启动。")
        return {}
    if not isinstance(data, dict):
        print("通讯录文件格式不正确，已按空通讯录启动。")
        return {}
    return data
```

三层依次是：**文件存在吗 → 能解析吗 → 是字典吗**。实测（用 `contacts.py` 里同款 `load_data` 验证）：

```text
文件不存在      -> {}
坏 JSON         -> {}（并打印“文件损坏”）
JSON 是 list    -> {}（并打印“格式不正确”）
正常 {"张三":"138"} -> {'张三': '138'}
```

`isinstance(data, dict)` 这一层很容易漏：`json.load` 对 `[]`、`"abc"` 都不会报错，但后面的 `data[name] = phone` 会崩。

### 写入

[07_file_test.py:20-23](../07_file_test.py#L20-L23)：

```python
def save_data():
    with open(FILE_NAME, "w", encoding="utf-8") as f:
        json.dump(contacts, f, ensure_ascii=False, indent=4)
    return {}
```

`ensure_ascii=False` 让中文原样写入；`indent=4` 让文件可读。`return {}` 没有调用方使用，属于冗余。

### 实际运行

输入：`1 → 李四 → 137… → 2 → 3 → 1 → 2 → 4`

```text
请选择操作（1/2/3/4）：请输入联系人姓名：请输入联系人电话：✅已保存：李四，电话：13700000000
...
--- 联系人列表 ---
姓名：李四，电话13700000000
...
---请选择要删除的联系人编号 ---
1.李四
请输入要删除的编号：✅已成功删除：李四
...
通讯录还是空的哦！
```

落盘结果：

```json
{
    "李四": "13700000000"
}
```

### ⚠️ v3 最大的坑：相对路径

`FILE_NAME = "contacts_data.json"`（[:4](../07_file_test.py#L4)）是**相对当前工作目录**，不是相对脚本位置。

实测：在 `elsewhere/` 目录里执行 `python ../07_file_test.py`，添加并删除「张三」后：

```text
✅已保存：张三，电话：13800000000
✅已成功删除：张三
```

程序一切正常，但**数据写到了 `elsewhere/contacts_data.json`**，脚本旁边的原文件仍是 `{}`。这就是「假装保存成功」：不报错，只是存错地方。

修法见 v4：用 `__file__` 算出脚本所在目录。

### 两处小回归

- 删除列表用回 `for i in range(len(names))`（[:52-53](../07_file_test.py#L52-L53)），v2 的 `enumerate` 丢了。
- 展示时少了一个冒号：「电话137…」（[:44](../07_file_test.py#L44)），v2 是「电话：138…」。

## 四、v4 `contacts.py`：业务函数不碰 `input()`

### 最重要的结构变化

| 之前 | 现在 |
| --- | --- |
| 函数内部 `input()` / `print()` | 业务函数只收参数、返回 `(ok, message)` |
| 全局 `contacts` | `contacts` 作为参数传入 |
| `save_data()` 无参数 | `save_data(path, contacts)` 返回 `True/False` |
| 相对路径 | `BASE_DIR = os.path.dirname(os.path.abspath(__file__))`（[:10-11](../contacts.py#L10-L11)） |

`add_contact` [contacts.py:45-55](../contacts.py#L45-L55)：

```python
def add_contact(contacts, name, phone):
    if not name:
        return False, "姓名不能为空"
    if not phone:
        return False, "电话不能为空"
    if name in contacts:
        return False, f"你添加的{name}已经存在了"
    contacts[name] = phone
    return True, f"已保存：{name}，电话：{phone}"
```

实测：

```text
空姓名 -> (False, '姓名不能为空')
空电话 -> (False, '电话不能为空')
重名   -> (False, '你添加的张三已经存在了')
新增   -> (True, '已保存：李四，电话：139')
名单   -> ['1.张三  电话：138', '2.李四  电话：139']
删 0   -> (False, '输入的编号超出范围了')
删 3   -> (False, '输入的编号超出范围了')
删 1   -> (True, '已成功删除：张三')
```

**不启动程序就能测业务逻辑**，这是 v4 相比 v2/v3 最大的收益。

### 路径修复实测

```text
BASE_DIR -> E:\python源码\python工作区\lreaning
```

无论从哪个目录运行，`contacts_data.json` 都固定落在脚本旁边。这解决了 v3 的「假装保存成功」。

### v4 仍可继续改的地方

1. `load_data` 里 `print()`（[:23](../contacts.py#L23)、[:27](../contacts.py#L27)）——库函数直接输出，调用方无法决定要不要提示。更干净的做法是返回 `(data, warning)` 或抛自定义异常。
2. 编号删除依赖**字典当前顺序**。`format_contacts` 和 `delete_contact` 各自 `list(contacts.keys())`，中间如果插入/删除过，编号含义可能变化；在单线程 CLI 里没问题，但这是「按编号删除」的固有脆弱点。
3. 电话只校验非空，没有格式校验；姓名允许重名外的任意字符。
4. `save_data` 失败只打印，调用方拿到了 `False` 却没处理（[:104](../contacts.py#L104)、[:132](../contacts.py#L132)）——可以提示用户「本次修改未保存」。

## 五、四个版本的对照结论

| 能力 | v1 | v2 | v3 | v4 |
| --- | --- | --- | --- | --- |
| 增 / 查 | ✓ | ✓ | ✓ | ✓ |
| 删除（按编号） | ✗ | ✓ | ✓ | ✓ |
| 持久化 | ✗ | ✗ | ✓ | ✓ |
| 路径正确 | — | — | ✗ | ✓ |
| 格式校验 | ✗ | ✗ | ✓ | ✓ |
| 业务函数可单测 | ✗ | ✗ | ✗ | ✓ |
| 输入清洗 | ✗ | 部分 | 部分 | ✓（`ask`） |

**演进的主线不是「功能越加越多」，而是「把副作用往外推」**：`input()`/`print()` 往 `main()` 推，文件路径往常量推，错误信息往返回值推。推到业务函数只剩「收参数、改数据、返结果」时，测试才成为可能（接 09 篇）。
