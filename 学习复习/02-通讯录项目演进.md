## 一、四个版本的运行取证

### v1 · dictionary-01.py

实际输出（喂入 `1 张三 13800000000 / 1 张三 999 / 2 / 3 / 9`）：

```text
请选择操作（输入1/2/3）：请输入联系人姓名：请输入联系人电话：✅已保存：张三的电话时13800000000
...
请选择操作（输入1/2/3）：请输入联系人姓名：你添加的张三已经存在！
...
请选择操作（输入1/2/3）：❌ 无效的选择，请重新输入
...
请选择操作（输入1/2/3）：--- 联系人列表 ---
姓名：张三,电话：13800000000
```

做对的：**先查重再写入**（[dictionary-01.py:17-21](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/dictionary-01.py#L17)）。你早先踩过「先存后判」导致新加的也提示已存在，这版已经改对了。

三个待改：

1. `:22` **`电话时` 是错别字**（应为「是」）。这类文案错误程序抓不到，只能自己读一遍输出。
2. `:28` `if len(contacts) == 0:` → **`if not contacts:`**。空字典本身就是 `False`，v2/v3/v4 里你其实已经改用了后者，说明你自己就纠正过。
3. `:32` `姓名：{name},电话：` 中英文逗号混用；输出里那个逗号是半角。统一全角或统一半角，别混。

字典速查（本文件全覆盖）：

| 操作 | 写法 | 注意 |
| --- | --- | --- |
| 存 | `contacts[name] = phone` | 键已存在则**覆盖**，所以要先查重 |
| 取 | `contacts.get(name, "无")` | 比 `contacts[name]` 安全，不 `KeyError` |
| 判存在 | `if name in contacts` | 只查**键**，不查值 |
| 删 | `del contacts[name]` | 键不存在会 `KeyError`；`contacts.pop(name, None)` 更安全 |
| 遍历 | `for k, v in contacts.items()` | 只要键用 `.keys()`，只要值用 `.values()` |
| 判空 | `if not contacts:` | 不要用 `len(...) == 0` |
| 编号列表 | `list(contacts.keys())` | 想按第几个操作时**必须转列表**，字典本身不能下标取 |

> ⚠️ `list(contacts.keys())` 的顺序是**插入顺序**（Python 3.7+ 保证）。但插入顺序不等于你想要的顺序，这正是 v4 遗留的设计隐患，见本文第三节。

### v2 · 06_function_contacts.py —— 封装对了，但传数据的方式不对

关键改进：[06_function_contacts.py:25-29](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/06_function_contacts.py#L25) 用 `enumerate` 打编号，比手动计数干净：

```python
names = list(contacts.keys())
for index, name in enumerate(names, start=1):
    print(f"{index}.{name}")
```

守卫式 `return` 也用对了（`:22-23`、`:34-35`、`:39-40`）——空通讯录、非数字、超范围三种情况各自提前退出，不再套三层 `if`。

**但两个结构性问题：**

```python
contacts = {}                 # :1  模块级全局变量

def add_contacts():           # :3  没有参数，没有返回值
    name = input("请输入联系人姓名：").strip()   # :4  函数自己伸手拿输入
    ...
    contacts[name] = phone    # :9  直接修改全局
```

| 问题 | 后果 |
| --- | --- |
| 函数内部读 `input()` | 想在测试里直接调用 `add_contacts()` 就必须**手动打字**，没法自动化 |
| 靠全局 `contacts` 传数据 | 函数不是一个自洽的单元：换个名字的全局字典它就操作错了对象，且**看不出函数需要什么、产出什么** |

实际输出里能看到「无校验」的代价（我喂的输入把 `3` 当姓名、`1` 当电话）：

```text
请输入联系人姓名：请输入联系人电话：✅已保存：3，电话：1
```

程序高高兴兴存下了一个叫「3」、电话是「1」的联系人。**姓名和电话没有任何格式校验**——v4 才补上姓名非空。

### v3 · 07_file_test.py —— 存盘了，但路径是相对路径

`load_data()` 的防御写得很好（[07_file_test.py:6-18](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/07_file_test.py#L6)），三层齐全：

```python
if not os.path.exists(FILE_NAME):        # ① 文件不存在 → 空启动
    return {}
try:
    with open(FILE_NAME, "r", encoding="utf-8") as f:
        data = json.load(f)
except (json.JSONDecodeError, OSError):  # ② 文件损坏/无权限 → 空启动
    print("通讯录文件损坏或无法读取，已按空通讯录启动。")
    return {}
if not isinstance(data, dict):           # ③ 内容是 [] 或 "abc" → 空启动
    print("通讯录文件格式不正确，已按空通讯录启动。")
    return {}
```

第 ③ 层特别值得表扬：空文件 `""` 让 `json.load` 抛 `JSONDecodeError`，但内容是 `[]` 或 `"abc"` 时 `json.load` **会成功返回**，等到后面 `name in contacts` 或 `contacts.items()` 才炸。提前 `isinstance` 拦掉，说明你已经理解「读成功 ≠ 读对了」。

**但这个文件有一个会丢数据的严重 bug：**

[07_file_test.py:4](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/07_file_test.py#L4) `FILE_NAME = "contacts_data.json"` 是**相对路径**——它相对的是「运行时的工作目录」，不是脚本所在目录。

我做了对照实验，结果如下：

```text
# 沙箱里脚本旁边放着数据：{"老联系人":"13800000000"}
# 从另一个目录 elsewhere/ 运行 07_file_test.py，添加「新同事」

请选择操作（1/2/3/4）：...✅已保存：新同事，电话：139     ← 程序说成功了

--- elsewhere/ 里冒出的文件：contacts_data.json
--- 那份新文件内容：{"新同事": "139"}
--- 脚本旁边那份（更新了吗）：{"老联系人":"13800000000"}    ← 原封不动！
```

**程序打印了「✅已保存」，但你的老数据一条都没读进来、新数据也没存进那个文件。** 它悄悄在旁边建了一个同名新文件。下次从原目录启动，「新同事」人间蒸发。这就是为什么 v3 看起来功能最全，实际最危险。

另外两处小毛病：

```python
def save_data():                          # :20 没有参数，偷偷用全局 contacts
    with open(FILE_NAME,"w",...) as f:
        json.dump(contacts, f, ...)
    return {}                             # :23 这个返回值毫无意义，应删掉
```

还有 [07_file_test.py:52-53](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/07_file_test.py#L52) 的编号用了手动 `range`：

```python
for i in range(len(names)):
    print(f"{i+1}.{names[i]}")
```

**这是相对 v2 的倒退**——v2 里你已经会写 `enumerate(names, start=1)` 了。改代码时把老的好写法丢掉，很常见，所以每次重构后要和上一版对一下清单。

### v4 · contacts.py —— 把「规则」写进了第一行

[contacts.py:1-5](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/contacts.py#L1) 的模块文档字符串就是这版的设计合同：

```python
"""简易通讯录：06_function_contacts.py 与 07_file_test.py 的整合版。

规则：业务函数只接收参数、返回结果，不碰 input()；
所有屏幕交互都集中在 main() 里，方便单独测试。
"""
```

对照实验证明 v4 修掉了 v3 的丢数据 bug（同样从 `elsewhere/` 运行）：

```text
请选择操作（1/2/3/4）：...已保存：另一个，电话：137

--- elsewhere/ 里的 json 变了吗：{"新同事": "139"}        ← 没被污染
--- 脚本旁边那份变了吗：{"老联系人":"13800000000", "另一个":"137"}   ← 正确合并
```

靠的是 [contacts.py:10-11](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/contacts.py#L10)：

```python
BASE_DIR = os.path.dirname(os.path.abspath(__file__))
FILE_NAME = os.path.join(BASE_DIR, "contacts_data.json")
```

**记住这一对**：`__file__` 是脚本自己的位置，`os.path.abspath` 把它变成绝对路径，`dirname` 取所在目录。数据文件永远锚在脚本旁边，与「你在哪个目录敲 python」无关。

分层效果（[contacts.py:45-55](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/contacts.py#L45)）：

```python
def add_contact(contacts, name, phone):
    """新增联系人，返回 (是否成功, 提示信息)。"""
    if not name:  return False, "姓名不能为空"
    if not phone: return False, "电话不能为空"
    if name in contacts: return False, f"你添加的{name}已经存在了"
    contacts[name] = phone
    return True, f"已保存：{name}，电话：{phone}"
```

这就是「数据层 / 业务层 / 交互层」三分的落地：

| 层 | v4 里的成员 | 职责 |
| --- | --- | --- |
| 数据层 | `load_data` `save_data` | 只管文件进出，别的一概不知 |
| 业务层 | `add_contact` `delete_contact` `format_contacts` | 只管规则，收参数、返结果，**不 print、不 input** |
| 交互层 | `main` `ask` | 只管问用户和显示结果 |

因为业务层不碰 `input`，现在可以**不开程序就测它**：

```python
from contacts import add_contact, delete_contact, format_contacts

c = {}
print(add_contact(c, "张三", "138"))        # (True, '已保存：张三，电话：138')
print(add_contact(c, "", "138"))            # (False, '姓名不能为空')
print(add_contact(c, "张三", "9"))          # (False, '你添加的张三已经存在了')
print(format_contacts(c))                    # ['1.张三  电话：138']
print(delete_contact(c, 5))                  # (False, '输入的编号超出范围了')
```

`c = load_data("不存在的路径")` 这类也不用真造文件——路径是参数，测试时可以传任何值。**这就是 v2 那版做不到的事。**

## 二、v4 仍然存在的问题（下一步的靶子）

1. **电话没校验**。`add_contact(contacts, "张三", "abc")` 会成功。补一行即可：

```python
    if not phone.isdigit():
        return False, "电话只能是数字"
```

2. **按「显示编号」删除，把 UI 和存储顺序绑死了**（[contacts.py:66-74](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/contacts.py#L66)）。删除编号来自 `list(contacts.keys())` 的位置，一旦以后加了排序（比如按姓名排），用户看到的 1 号就和代码里的 1 号对不上，会删错人。两条出路：
   - 用**姓名**定位（你现在已经有 `if name in contacts` 的能力了）；
   - 或给每条联系人一个真正稳定的 `id`（学完类之后，`Contact` 对象带 `id` 就是自然解法）。

3. **没有「修改」和「查询」**。菜单只有增 / 看 / 删，这是最容易加的两个功能，且能直接复用 `add_contact` 的模式。

4. **`contacts_data.json` 里如果混进非字符串的值**（比如手工写成数字），`format_contacts` 照样打印，不会报错——读的时候没做值级校验。

## 三、这条主线教给你的三个通用道理

| 道理 | 在本类里的证据 |
| --- | --- |
| **「保存成功」的提示不等于保存对了地方** | v3 打印 ✅已保存，数据却写进了另一个目录的新文件 |
| **函数带参数、有返回值，才可测试** | v2 的 `add_contacts()` 无法测；v4 的 `add_contact(c, 名字, 电话)` 可以 |
| **重构时要做减法检查** | v3 把 v2 的 `enumerate` 退回手动 `range`；把 `if not contacts` 退回 `len(...) == 0` |
