## 一、15_class_dog.py —— 最小可用的类

整个类只有 8 行 [15_class_dog.py:1-8](../15_class_dog.py#L1-L8)：

```python
class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age = age
    def sit(self):
        print(f"{self.name}乖乖坐下了。")
    def bark(self):
        print(f"{self.name}汪汪叫！它今年{self.age}岁了。")

my_dog = Dog("旺财", 3)      # :10
your_dog = Dog("大黄", 5)    # :11

my_dog.bark()                # :13
your_dog.sit()               # :14
```

实际输出（`python -u 15_class_dog.py`，exit=0）：

```text
旺财汪汪叫！它今年3岁了。
大黄乖乖坐下了。
```

### 这个输出证明了三件事

| 现象 | 说明的原理 |
| --- | --- |
| 代码里没有手写 `__init__()` 调用，但 `self.name` 有值 | 实例化时 `__init__` 被**自动执行** |
| `"旺财"` 进了 `name`，`3` 进了 `age` | 实参按**位置**匹配形参，顺序不能错 |
| `my_dog.bark()` 说旺财 3 岁，`your_dog.sit()` 说大黄 | 两个对象各持一份数据，**互不干扰** |

最后一条是 `self` 存在的意义。直接用 `__dict__` 看（实测）：

```text
my_dog.__dict__   -> {'name': '旺财', 'age': 3}
your_dog.__dict__ -> {'name': '大黄', 'age': 5}
```

两个不同的字典，挂在两个不同的对象上。`sit` / `bark` 不在里面——方法只在 `Dog` 类里存一份，通过 `self` 找到「当前这个对象」的数据。

`my_dog.bark()` 与 `Dog.bark(my_dog)` 是同一件事：点号前面的对象会被**自动**塞进第一个参数 `self`。这也是为什么定义方法时第一个参数必须留位置。

## 二、16_class_cat.py —— 四个进阶动作各做了一遍

### 2.1 先看整份输出

```text
优米原来的颜色：黄色
优米现在的颜色：黑色
黑色的，优米喵喵叫！
白色的，悠米睡觉了！
悠悠米正在喝奶，它才3个月大！
暖色的，悠悠米喵喵叫！
🔋悠悠米正在充电，不睡觉！
```

### 2.2 外部改属性：`my_cat.color = "黑色"`

[16_class_cat.py:13-15](../16_class_cat.py#L13-L15)：

```python
print(f"优米原来的颜色：{my_cat.color}")
my_cat.color = "黑色"          # 直接从类外面改，Python 不拦
print(f"优米现在的颜色：{my_cat.color}")
```

改完之后，第 3 行输出立刻变成「黑色的」——**外部改的属性，被类内部的方法读到了**。因为 `self.color` 每次调用时都去对象的 `__dict__` 现查，不是创建方法时就固定住。

这也解释了为什么 `your_cat` 仍是「白色的」：改的是 `my_cat` 这一个对象的字典，不是 `Cat` 类。

### 2.3 继承那段逐行读

[16_class_cat.py:19-32](../16_class_cat.py#L19-L32)：

```python
class ElectricCat(Cat):                    # :19 括号里写父类
    def __init__(self, name, color):
        super().__init__(name, color)      # :21 让 Cat 帮忙存 name/color
        self.age = 3                       # :22 子类独有的新属性
    def drink_milk(self):                  # :23 新方法
        print(f"{self.name}正在喝奶，它才{self.age}个月大！")
    def sleep(self):                       # :25 重写父类同名方法
        print(f"🔋{self.name}正在充电，不睡觉！")

my_cat_age = ElectricCat("悠悠米", "暖色")  # :27
my_cat_age.drink_milk()                     # :29
my_cat_age.neow()                           # :31 继承来的
my_cat_age.sleep()                          # :32 重写过的
```

最后三行恰好把三种情况各演示一次：

| 方法 | 来源 | 输出证据 |
| --- | --- | --- |
| `drink_milk` | 子类**新增** | `悠悠米正在喝奶，它才3个月大！` |
| `neow` | 从父类**继承**，没改 | `暖色的，悠悠米喵喵叫！` |
| `sleep` | 子类**重写** | `🔋悠悠米正在充电，不睡觉！`（父类的「睡觉了」被替换） |

`super()` 不是可有可无的装饰：如果不写 `:21`，`self.name` 和 `self.color` 根本不会存在，`:24` 的 `self.name` 会直接 `AttributeError`。

### 2.4 `isinstance` 与 `type`

用这两个类实测：

```text
isinstance(my_cat_age, Cat)        -> True      # 继承链上层层都算
isinstance(my_cat, ElectricCat)    -> False     # 父类实例不算子类
type(my_cat_age) is Cat            -> False     # type 只认亲生的类
type(my_cat_age) is ElectricCat    -> True
```

**判类型一律用 `isinstance`**，因为它尊重继承；`type(x) is C` 在子类对象上会给出 False，几乎不是你想要的结果。

## 三、这两个文件里的四个实际问题

### 问题 1：`age` 放进了子类，普通猫根本没有

`age` 是猫的通用属性，却只写在 `ElectricCat.__init__` 里 [16_class_cat.py:22](../16_class_cat.py#L22)。实测：

```text
my_cat = Cat("优米", "黄色")
my_cat.age  ->  AttributeError: 'Cat' object has no attribute 'age'
```

同一个设计还带来第二个后果：`ElectricCat` 的构造函数只收 `name, color`，想传年龄会直接报错：

```text
ElectricCat("小电", "蓝色", 5)
-> TypeError: ElectricCat.__init__() takes 3 positional arguments but 4 were given
```

规则：**所有子类都该有的属性，放在父类的 `__init__` 里**；子类只加自己特有的。改法：

```python
class Cat:
    def __init__(self, name, color, age=3):
        self.name = name
        self.color = color
        self.age = age

class ElectricCat(Cat):
    def __init__(self, name, color, age=3, battery=100):
        super().__init__(name, color, age)   # 把 age 交上去
        self.battery = battery
```

### 问题 2：`self.age = 3` 硬编码，每只电子猫都三岁

`age` 写死成 3，于是 `ElectricCat("大橘", "橘色")` 和 `ElectricCat("小白", "白色")` 永远同龄。实测两只实例的 `age` 都是 `3`。

「所有对象都一样的值」有三个落点，按场景选：

```python
class ElectricCat(Cat):
    age = 3                                   # 1. 类属性：全部共享，可整体改
    def __init__(self, name, color, age=3):   # 2. 默认参数：每只可不同
        super().__init__(name, color, age)
        self.age = age
```

推荐第 2 种：不传就用 3，传了就以传入值为准。写死字面量只在「业务上确实永不相同」时才用，而且应该写注释说明原因。

### 问题 3：方法名 `neow` 是拼错的 `meow`

[16_class_cat.py:5](../16_class_cat.py#L5) 定义 `def neow`，`:16`、`:31` 也调用 `neow`。**错得很一致，所以程序完全正常**：

```text
my_cat.meow()  ->  AttributeError: 'Cat' object has no attribute 'meow'
my_cat.neow()  ->  黑色的，优米喵喵叫！
```

这正是它难被发现的原因：方法名拼错，只要定义和调用两头一致就不报错。代价是以后搜「猫叫」相关代码搜 `meow` 什么都找不到，别人读代码也会以为 `neow` 是什么术语。

> 和 05 号文档里 `"Uers-agent"` 是同一类病：**字符串当标识符的地方打错，程序不报错**。区别是方法名可以用编辑器的重命名（F2）一次全改，字典键和 HTML 类名往往改不全。

### 问题 4：`"黑色的，优米喵喵叫！"` 的语序

属性当修饰语放句首，主语被推迟到最后，读起来像半句话。把名字放最前：

```python
def meow(self):
    print(f"{self.name}（{self.color}）喵喵叫！")   # 优米（黄色）喵喵叫！
```

文案类的毛病程序永远不会提醒你，**把真实输出读一遍**比读代码更容易发现。

## 四、该补的一处：`__str__`

现在 `print(my_cat)` 得到的是（实测同类对象）：

```text
<catmod.Cat object at 0x000000000148D400>
```

地址每次运行都不同，对人没有任何信息量。加一个 `__str__`：

```python
def __str__(self):
    return f"{self.name}（{self.color}，{self.age}岁）"
```

实测输出：

```text
优米（黄色，3岁） | 悠悠米（暖色，3岁）
```

`print(对象)`、`f"{对象}"`、`str(对象)` 都会走 `__str__`。调试时能直接看出这个对象是谁，比在 `print` 里手拼字段省事。
