## 一、15_class_dog.py —— 最小可用的类

[15_class_dog.py:1-14](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/15_class_dog.py#L1)：

```python
class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age = age
    def sit(self):
        print(f"{self.name}乖乖坐下了。")
    def bark(self):
        print(f"{self.name}汪汪叫！它今年{self.age}岁了。")

my_dog = Dog("旺财", 3)
your_dog = Dog("大黄", 5)

my_dog.bark()
your_dog.sit()
```

实际输出：

```text
旺财汪汪叫！它今年3岁了。
大黄乖乖坐下了。
```

### 这个输出证明了三件事

| 现象 | 说明的原理 |
| --- | --- |
| `Dog("旺财", 3)` 里没有 `__init__` 的调用痕迹，但 `self.name` 有值 | `__init__` 在实例化时**自动执行** |
| `"旺财"` 进了 `name`、`3` 进了 `age` | 实参按**位置**匹配形参，顺序不能错 |
| `my_dog.bark()` 显示 3 岁、`your_dog.sit()` 说「大黄」 | 两个对象各自持有 `name/age`，**互不干扰** |

最后一条是 `self` 的存在意义。用 `__dict__` 直接看（实测）：

```text
my_dog.__dict__   -> {'name': '旺财', 'age': 3}
your_dog.__dict__ -> {'name': '大黄', 'age': 5}
```

**两个不同的字典，挂在两个不同的对象上。** 方法 `sit` / `bark` 不在里面——它们只存在 `Dog` 类里一份，通过 `self` 拿到「当前这个对象」的数据。这就是「数据按对象存、代码按类共享」。

### 唯一该补的一处：`__str__`

现在 `print(my_dog)` 会得到（实测同类对象）：

```text
<__main__.ElectricCat object at 0x00000000014D8EC0>
```

调试时完全没用。加一个（写法见大文档「神功 1」）：

```python
    def __str__(self):
        return f"{self.name}（{self.age} 岁的狗）"
```

## 二、16_class_cat.py —— 你已经把四个进阶动作都做了一遍

[16_class_cat.py:13-16](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/16_class_cat.py#L13) 改属性：

```python
print(f"优米原来的颜色：{my_cat.color}")
my_cat.color = "黑色"          # 直接从外面改，Python 不拦
print(f"优米现在的颜色：{my_cat.color}")
```

实际输出（整份文件跑一遍）：

```text
优米原来的颜色：黄色
优米现在的颜色：黑色
黑色的，优米喵喵叫！           ← 改完立刻生效，且影响的是方法里的 self.color
白色的，悠米睡觉了！
悠悠米正在喝奶，它才3个月大！
暖色的，悠悠米喵喵叫！
🔋悠悠米正在充电，不睡觉！
```

第 3 行值得停一下：**外部改的属性，被内部的方法读到了**。因为 `self.color` 每次调用时都是去对象的 `__dict__` 里现查，不是创建方法时就固定了。

### 继承那段（`:19-31`）逐行读

```python
class ElectricCat(Cat):                    # :19 括号里写父类 = 子承父业
    def __init__(self, name, color):
        super().__init__(name, color)      # :21 让 Cat 帮它存 name/color
        self.age = 3                       # :22 子类独有的新属性
    def drink_milk(self):                  # :23 新方法
        print(f"{self.name}正在喝奶，它才{self.age}个月大！")
    def sleep(self):                       # :25 重写父类同名方法
        print(f"🔋{self.name}正在充电，不睡觉！")

my_cat_age = ElectricCat("悠悠米", "暖色")
my_cat_age.drink_milk()
my_cat_age.neow()          # :30 ← 这个方法没重写，是从 Cat 继承来的
my_cat_age.sleep()         # :31 ← 这个重写了
```

输出最后三行正好把三种情况各演示了一遍：

| 方法 | 来源 | 输出证据 |
| --- | --- | --- |
| `drink_milk` | 子类新增 | `悠悠米正在喝奶，它才3个月大！` |
| `neow` | **继承**父类未改 | `暖色的，悠悠米喵喵叫！` |
| `sleep` | **重写**父类 | `🔋悠悠米正在充电，不睡觉！`（父类那句「睡觉了」被替换） |

`isinstance` / `type` 的区别，用你这两个类实测：

```text
isinstance(electric_cat, Cat)   -> True      （继承链上层层都算）
isinstance(cat, ElectricCat)    -> False     （父类不算子类，方向不能反）
type(electric_cat) is Cat       -> False     （type 只认亲生的那个类）
type(electric_cat) is ElectricCat -> True
```

**判类型一律用 `isinstance`**，因为它尊重继承。

## 三、这两个文件里的四个实际问题

### 问题 1：`age` 放错了地方（实测会崩）

`age` 是「猫」的通用属性，却被写进了子类 `ElectricCat.__init__`（`:22`）。后果：普通 `Cat` 对象**根本没有 `age`**。

```text
c = Cat("优米", "黄色")
c.age  ->  AttributeError: 'Cat' object has no attribute 'age'
```

**规则：所有子类都该有的属性，放在父类的 `__init__` 里。** 改法：

```python
class Cat:
    def __init__(self, name, color, age=3):    # 默认值写在形参上
        self.name = name
        self.color = color
        self.age = age

class ElectricCat(Cat):
    def __init__(self, name, color, age=3, battery=100):
        super().__init__(name, color, age)     # 把 age 交上去
        self.battery = battery
```

### 问题 2：`self.age = 3` 硬编码，每只电子猫都三龄

`:22` 把 3 写死在构造函数里。我造了两只验证：

```text
两个 ElectricCat 的 age 都是  3 3
```

**「所有对象都一样的值」是类属性或默认参数的信号**，不该塞在 `__init__` 里当字面量。三个选择，按场景挑：

```python
class ElectricCat(Cat):
    age = 3                              # ① 类属性：全都一样，且可整体改
    def __init__(self, name, color, age=3):    # ② 默认参数：每只可不同，不给就用 3
        super().__init__(name, color)
        self.age = age                   # ③ 想强制每只一致才用硬编码，但要写注释说明为什么
```

推荐 ②：`ElectricCat("悠悠米", "暖色")` 用默认 3，`ElectricCat("大橘", "橘色", 8)` 传 8。

### 问题 3：方法名 `neow` 是拼错的 `meow`

[16_class_cat.py:5](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/16_class_cat.py#L5) 定义 `def neow`，`:16` 和 `:30` 也调用 `neow`——**错得很一致，所以程序完全正常**。

这正是它难被发现的原因：拼错的**方法名不会报错**，只要定义和调用两头一致。代价是：以后你想搜「猫叫」相关代码，搜 `meow` 什么都找不到；别人读你的代码会以为是某种专业术语。

> 📌 和 05 号文档里 `"Uers-agent"` 是同一类病：**「字符串当标识符」的地方打错，程序不报错**。区别在于属性名/方法名至少能用编辑器的重命名（F2）一次性全改，而字典键、HTML 类名改不全。

### 问题 4：`f"{self.color}的，{self.name}喵喵叫！"` 的语序把主语切断了

输出是 `黑色的，优米喵喵叫！`——读起来像半句话。属性当修饰语放句首，会让「谁在做这件事」延迟出现。建议把名字放最前：

```python
    def meow(self):
        print(f"{self.name}（{self.color}）喵喵叫！")     # 优米（黄色）喵喵叫！
```

另外逗号后多余的空格、以及「的，」这个组合，是中文输出里常见的机械感来源。写输出文案时**把真实输出读一遍**，比读代码本身更能发现这类问题。
