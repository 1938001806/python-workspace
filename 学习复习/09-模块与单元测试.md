# 09 · 模块与单元测试（`my_math.py` + `test_my_math.py`）

> 类别定位：把函数放进模块 → 用 `unittest` 证明它真的对 → 数清楚「跑了几个」。
> 两个文件都真实运行过；本篇每个结论都有一次实测，尤其关注「测试静默消失」这类不报错的失败。

## 本类文件

| 文件 | 行数 | 作用 | 状态 |
| --- | --- | --- | --- |
| [my_math.py](../my_math.py) | 10 | `add` / `subtract` / `multiply` / `divide` | 能跑；只有 `divide` 做了除零校验 |
| [test_my_math.py](../test_my_math.py) | 23 | 4 个测试方法 | 4 个全过；但覆盖的边界很少 |

仓库里 `my_math.py` / `test_my_math.py` 各只有一份（`find` 实测）：

```text
./my_math.py
./test_my_math.py
```

## 一、三种跑法，结果一致：`Ran 4 tests`

```text
python test_my_math.py -v
python -m unittest -v test_my_math
python -m unittest discover -v
```

三种都输出：

```text
test_add (test_my_math.TestMathFunctions.test_add) ... ok
test_divide (test_my_math.TestMathFunctions.test_divide) ... ok
test_multiply (test_my_math.TestMathFunctions.test_multiply) ... ok
test_subtract (test_my_math.TestMathFunctions.test_subtract) ... ok

----------------------------------------------------------------------
Ran 4 tests in 0.001s

OK
```

**每次改完测试，第一件事是看 `Ran N tests` 里的 N。** 下面的 `OK` 只说明「跑过的都过了」，不说明「你写的都跑了」。0 个测试也会显示 `OK`。

## 二、命名规则：前缀是 `test`，不是 `test_`

建一个临时文件实测：

```python
class T(unittest.TestCase):
    def testlower(self):  ...
    def test_upper(self): ...
    def _test_lead(self): ...
    def TestCap(self):    ...
    def notest(self):     ...
```

`python -m unittest -v test_naming` 实际只收集了两个：

```text
test_upper ... ok
testlower  ... ok
Ran 2 tests
```

规则拆开看：

| 条件 | 说明 |
| --- | --- |
| 类必须继承 `unittest.TestCase` | 不继承的类，即使方法叫 `test_y` 也不会被收集（实测：`Ran 1 test`，只有那个继承了的） |
| 方法名以 `test` 开头 | `testlower` 会被收集；`_test_lead`（下划线开头）不会 |
| 大小写敏感 | `TestCap` 不会 |
| 文件名匹配 `test*.py` | `discover` 默认只扫这个模式；`check_hidden.py` 里的测试完全不会被发现，显式 `python -m unittest check_hidden` 才会跑 |

模块级的 `def test_z()` 也不会被收集——测试必须是 `TestCase` 的方法。

## 三、`test_divide` 里塞了两件事

[test_my_math.py:16-20](../test_my_math.py#L16-L20)：

```python
def test_divide(self):
    self.assertEqual(divide(10, 2), 5)

    with self.assertRaises(ValueError):
        divide(10, 0)
```

一个测正常路径，一个测异常路径。失败时你只知道「`test_divide` 挂了」，不知道是除法结果错了还是除零没抛。拆成两个：

```python
def test_divide(self):
    self.assertEqual(divide(10, 2), 5)

def test_divide_by_zero(self):
    with self.assertRaises(ValueError):
        divide(10, 0)
```

一个测试只验证一个行为，失败信息才有定位价值。

## 四、`assertRaises` 必须带 `with`

[test_my_math.py:19](../test_my_math.py#L19) 写对了。漏掉 `with` 会怎样？实测：

```python
r = self.assertRaises(ValueError)
print(type(r).__name__)
```

```text
返回值: _AssertRaisesContext
errors: 0  failures: 0
```

它只是**创建了一个上下文对象**，里面的代码一行都没执行，测试当然通过。这是最阴的假绿灯：看起来在测异常，实际什么都没测。

正确写法只有两种：

```python
with self.assertRaises(ValueError):
    divide(10, 0)

# 或者
self.assertRaises(ValueError, divide, 10, 0)
```

### 期望的异常类型写错，会记成 error 而不是 failure

把 `ValueError` 写成 `ZeroDivisionError`：

```python
with self.assertRaises(ZeroDivisionError):
    divide(10, 0)
```

实测结果：

```text
testsRun: 1  errors: 1  failures: 0

ValueError: 不能除以0
```

`divide` 抛的是 `ValueError`，不是 `ZeroDivisionError`。注意它落在 **errors** 而不是 failures：异常类型不匹配时，`assertRaises` 把原异常继续抛出，unittest 记为 error。看报告时两个计数都要看。

## 五、当前实现的真实边界（逐条实测）

`divide` [my_math.py:7-10](../my_math.py#L7-L10) 只检查了 `b == 0`：

```python
def divide(a, b):
    if b == 0:
        raise ValueError("不能除以0")
    return a / b
```

实测：

```text
divide(10, 0)    -> ValueError: 不能除以0
divide(10, 0.0)  -> ValueError: 不能除以0     # 0.0 == 0 为 True
divide(0, 0)     -> ValueError: 不能除以0
divide(10, "2")  -> TypeError: unsupported operand type(s) for /: 'int' and 'str'
divide(10, None) -> TypeError: unsupported operand type(s) for /: 'int' and 'NoneType'
```

其他三个函数连除零这种检查都没有：

```text
add("a", "b")      -> 'ab'
multiply(3, "x")   -> 'xxx'
add(0.1, 0.2) == 0.3 -> False
```

`add("a","b")` 返回 `'ab'` 不是崩溃，而是 Python 的 `+` 对字符串也成立。对一个数学模块来说，这是**静默的错类型**：调用方拿到字符串，继续往下算才会炸，而且炸的位置离根因很远。

## 六、测试逼出来的第一个真问题：`divide` 没有类型校验

当前 `divide(10, "2")` 抛 `TypeError`，看起来「也报错了」，但错误信息是 Python 解释器给的 `unsupported operand type(s)`，不是模块自己的契约。更明确的写法：

```python
def _check_number(value, name):
    if isinstance(value, bool) or not isinstance(value, (int, float)):
        raise TypeError(f"{name} 必须是数字，收到 {type(value).__name__}")
    if value != value or value in (float("inf"), float("-inf")):
        raise ValueError(f"{name} 必须是有限数，收到 {value}")

def divide(a, b):
    _check_number(a, "a")
    _check_number(b, "b")
    if b == 0:
        raise ValueError("除数不能为 0")
    return a / b
```

三个设计决定：

- `isinstance(value, bool)` 单独挡掉：`True` 是 `int` 的子类，`divide(True, 2)` 会得到 0.5，通常不是本意。
- `nan` 用 `value != value` 检测（`nan != nan` 为 True）；`inf` 用成员判断。
- 异常类型区分「类型不对」（`TypeError`）和「值不对」（`ValueError`），调用方可以分别处理。

同样的检查应该给 `add` / `subtract` / `multiply`，否则 `add("a","b")` 仍然会静默返回 `'ab'`。

## 七、浮点断言：`assertEqual` 会红，`assertAlmostEqual` 才稳

实测：

```python
self.assertEqual(0.1 + 0.2, 0.3)
```

```text
FAIL: test_float
AssertionError: 0.30000000000000004 != 0.3
```

改成：

```python
self.assertAlmostEqual(0.1 + 0.2, 0.3)
```

通过。`assertAlmostEqual` 默认比较到 7 位小数，可用 `places=` 调整。

规则：整数、字符串、布尔用 `assertEqual`；浮点结果用 `assertAlmostEqual`，或者先 `round` 到业务精度再比（但要知道 `round` 也有二进制问题，见 08 号文档）。

## 八、`assert` 和测试断言不是一回事

```text
python -c "assert 1 == 2"       -> AssertionError，exit=1
python -O -c "assert 1 == 2"    -> 什么都不发生，exit=0
```

`python -O` 会删除所有 `assert` 语句。`unittest` 的 `assertEqual` / `assertRaises` 是**方法调用**，不是 `assert` 语句，所以在 `-O` 下仍然有效。

推论：

- 生产环境的参数校验用 `raise`，不要用 `assert`（见 07 号文档）。
- 测试里的断言用 `self.assertXxx`，不要用裸 `assert`，这样 `-O` 下测试仍然会失败。

## 九、模块从哪里来：`-m` 看当前目录，直接跑看脚本目录

先确认实际加载的文件：

```text
my_math 实际来自: E:\python源码\python工作区\lreaning\my_math.py
```

两种入口的搜索根不同：

| 跑法 | `sys.path[0]` | 结果 |
| --- | --- | --- |
| `python test_my_math.py`（任意 cwd） | 脚本所在目录 | 能找到同目录的 `my_math.py`，实测 `Ran 4 tests OK` |
| `python -m unittest test_my_math` | 当前工作目录 | cwd 不在仓库时，`ModuleNotFoundError: No module named 'test_my_math'` |
| `python test_my_math.py`（cwd 在仓库） | 仓库目录 | 也能找到，结果相同 |

从 `/tmp` 用 `-m` 跑的实测尾部：

```text
ImportError: Failed to import test module: test_my_math
ModuleNotFoundError: No module named 'test_my_math'

Ran 1 test in 0.000s

FAILED (errors=1)
```

注意它仍然说 `Ran 1 test`——导入失败也算了一个「测试」。这就是为什么不能只看 `OK/FAILED`，要看错误正文。

结论：**在项目根目录跑 `python -m unittest`**，或者用 `python -m unittest discover -s 项目路径 -t 项目路径` 显式指定起点。

## 十、完整改进版测试（8 个用例，已实测）

```python
import unittest
from my_math import add, subtract, multiply, divide


class TestMathFunctions(unittest.TestCase):
    def test_add(self):
        self.assertEqual(add(2, 3), 5)
        self.assertEqual(add(-1, 1), 0)

    def test_subtract(self):
        self.assertEqual(subtract(10, 5), 5)
        self.assertEqual(subtract(5, 10), -5)

    def test_multiply(self):
        self.assertEqual(multiply(3, 4), 12)
        self.assertEqual(multiply(0, 99), 0)

    def test_divide(self):
        self.assertEqual(divide(10, 2), 5)
        self.assertEqual(divide(-9, 3), -3)

    def test_divide_by_zero_int(self):
        with self.assertRaises(ValueError):
            divide(10, 0)

    def test_divide_by_zero_float(self):
        with self.assertRaises(ValueError):
            divide(10, 0.0)

    def test_divide_wrong_type(self):
        with self.assertRaises(TypeError):
            divide(10, "2")

    def test_float_precision(self):
        self.assertAlmostEqual(add(0.1, 0.2), 0.3)


if __name__ == "__main__":
    unittest.main()
```

实测：

```text
test_add ... ok
test_divide ... ok
test_divide_by_zero_float ... ok
test_divide_by_zero_int ... ok
test_divide_wrong_type ... ok
test_float_precision ... ok
test_multiply ... ok
test_subtract ... ok

Ran 8 tests in 0.000s

OK
```

比原来的 4 个多覆盖了：负数、乘零、`0.0` 除零、错误类型、浮点精度。`test_divide_wrong_type` 目前能过，是因为 Python 自己抛 `TypeError`；如果按第六节加了显式校验，这条测试会继续通过，且错误信息更清楚。

## 十二、要点清单

| 要点 | 证据 |
| --- | --- |
| 改完测试先看 `Ran N tests` 的 N | 导入失败也会显示 `Ran 1 test`，`OK` 不代表都跑了 |
| 测试方法必须以 `test` 开头 | `testlower` 收集，`_test_lead` / `TestCap` 不收集 |
| 类必须继承 `unittest.TestCase` | 不继承时 `test_y` 也不跑 |
| `discover` 只认 `test*.py` | `check_hidden.py` 不被发现 |
| `assertRaises` 必须带 `with` | 不带时返回 `_AssertRaisesContext`，0 失败 |
| 异常类型写错记为 error | `ZeroDivisionError` 应为 `ValueError` 时 `errors: 1` |
| 浮点用 `assertAlmostEqual` | `assertEqual(0.1+0.2, 0.3)` 实测失败 |
| `-O` 只删 `assert` 语句 | `self.assertXxx` 不受影响 |
| `-m` 的搜索根是 cwd | 换目录后 `ModuleNotFoundError` |
| 类型错误要显式校验 | `add("a","b") -> 'ab'`，不崩但错 |
