## 1. `Ran 4 tests` —— 数一数

三个数法实测都等于 4：

```python
import unittest
import test_my_math as tm
ldr = unittest.TestLoader()
print(ldr.loadTestsFromName("test_my_math").countTestCases())        # 4
print(ldr.loadTestsFromTestCase(tm.TestMathFunctions).countTestCases())  # 4
print(len([n for n in dir(tm.TestMathFunctions) if n.startswith("test_")]))  # 4
```

⚠️ 这条自检只在你**改了测试**之后有用：加了一个方法，三个数字必须同时从 4 变 5。哪个没变，就说明那个方法名没被收集（第 7 节）。

## 2. 命名规则比你想的松：前缀是 `test`，不是 `test_`

实测：

```python
import unittest
class C(unittest.TestCase):
    def tests_add(self): pass     # 多写了个 s
    def add_test(self): pass      # 前缀写在后面
    def test_1_ok(self): pass     # 后面跟数字
def flat(s, acc):
    for t in s:
        if isinstance(t, unittest.TestSuite): flat(t, acc)
        else: acc.append(t.id().split(".", 2)[-1])
    return acc
print(unittest.TestLoader().testMethodPrefix)     # 'test'
print(flat(unittest.TestLoader().loadTestsFromTestCase(C), []))
```

实测输出：

```
'test'
['test_1_ok', 'tests_add']
```

`tests_add` **被收了**（`startswith('test')` 就够），`add_test` **没被收**。两个危险推论：

- 你把方法写成 `check_add`、`add_test`、`testAdd`（驼峰，`testadd` ≠ `test`... `testAdd` 其实以 `test` 开头，会被收），收集规则和你想的不一样；
- ⚠️ **拼错方法名不会提醒你**。你以为改名成 `_test` 结尾更清楚，结果它悄悄不跑了，测试数还是原来的数（第 1 节那条自检就是防这个）。

约定就一条：**方法名一律 `test_` + snake_case**，别自创风格。

## 4. ⚠️ `assertRaises` 最常见的写法错误

你的 `with self.assertRaises(ValueError):` 是对的。两种错误写法实测：

```python
import unittest

class T(unittest.TestCase):
    def runTest(self): pass

b = T("runTest").assertRaises(ValueError)      # 忘了 with
print(type(b).__name__)                         # _AssertRaisesContext
```

`assertRaises(ValueError)` 不带 `with`、也不传第二个参数时，**只返回一个 context 对象，什么都不检查**——而且不会报错。写进测试里就是**永远绿灯**。

正确形式有三种，别混：

```python
import unittest
from my_math import divide           # 需要 my_math.py 在同一目录

class ThreeForms(unittest.TestCase):
    def test_form_1(self):
        with self.assertRaises(ValueError):            # ① 推荐
            divide(10, 0)

    def test_form_2(self):
        self.assertRaises(ValueError, divide, 10, 0)   # ② 函数和参数分开传

    def test_form_3(self):
        self.assertRaises(ValueError, lambda: divide(10, 0))  # ③ 需要 lambda

if __name__ == "__main__":
    unittest.main()
```

实测 `python -m unittest -v`：`Ran 3 tests ... OK`——三种写法都能抓到 `divide(10, 0)` 的 `ValueError`。

⚠️ ②③ 里 `divide(10, 0)` **不能带括号**写在参数位置——`self.assertRaises(ValueError, divide(10, 0))` 会在传参前就抛出，测试直接 ERROR。

## 5. 缺的用例清单（每条都实测过当前行为）

| 输入 | 当前结果 | 该断言什么 |
|---|---|---|
| `add(0.1, 0.2)` | `0.30000000000000004` | `assertAlmostEqual(a, b, places=10)` |
| `add("2", "3")` | `'23'`（字符串拼接） | 传错类型时该炸：`assertRaises(TypeError, add, "2", "3")` |
| `divide(5, 0.0)` | `ValueError` ✓（`0.0 == 0` 成立） | 已覆盖 |
| `divide(True, True)` | `1.0`（`bool` 是 `int` 子类） | 传 bool 要不要拒绝，你得**先决定**再写测试 |
| `multiply(3, 1e308)` | `inf` | 要不要管溢出，先决定 |

⚠️ 关于 `add("2","3")`：`assertEqual(add('2','3'), 5)` 实测**会失败**（`'23' != 5`，报错信息 `AssertionError: 23 != '23'`... 准确是 `AssertionError: '23' != 5`）。所以别以为「类型不对就一定测不出来」——**你测了就能看到**。真正危险的是 `assertEqual(add('2','3'), '23')` 这种「把当前的错行为当成期望行为」的断言：绿灯，但函数根本不是加法。

浮点那条实测（Python 3.15.0）：

```
AssertionError: 0.30000000000000004 != 0.3
```

修法：

```python
    def test_add_float(self):
        self.assertAlmostEqual(add(0.1, 0.2), 0.3, places=10)   # ✅
        # 千万别写 assertEqual(add(0.1, 0.2), 0.3) —— 会红
```

## 6. 测试逼出来的第一个真 bug：`divide` 没校验类型

先加一个测试：

```python
    def test_rejects_string(self):
        with self.assertRaises(TypeError):
            add("2", "3")        # 现在不抛 → 测试红
```

跑一下（实测）：

```
FAIL: test_rejects_string ...
AssertionError: TypeError not raised
```

**`TypeError not raised` 这句就是测试在告诉你：函数比你以为的宽松。** 修法是在函数里加边界检查，然后测试变绿：

```python
def divide(a, b):
    if not isinstance(a, (int, float)) or isinstance(a, bool):
        raise TypeError(f"a 必须是数字，收到 {type(a).__name__}")
    if b == 0:
        raise ValueError("不能除以0")
    return a / b
```

`isinstance(a, bool)` 这条单独挡，是因为 `isinstance(True, int)` 是 `True`——`bool` 是 `int` 的子类（[06-面向对象入门.md](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/%E5%AD%A6%E4%B9%A0%E5%A4%8D%E4%B9%A0/06-%E9%9D%A2%E5%90%91%E5%AF%B9%E8%B1%A1%E5%85%A5%E9%97%A8.md) 末尾提过）。要不要拒绝 `True`，是**你定的规矩**，测试只是把它写下来。

## 7. ⚠️ 让测试「静默消失」的四种写法（实测）

| 写法 | 结果 |
|---|---|
| `class MyTests:`（忘了继承 `unittest.TestCase`） | 完全不收集，0 tests |
| `class MyTests(unittest.TestCase)` 但方法叫 `add_test` | 该测试不跑（第 2 节实测） |
| 文件叫 `my_test.py`（不是 `test_*.py`） | `discover` 找不到它 |
| 删掉 `if __name__ == '__main__': unittest.main()` | `python 文件.py` 静默跑 0 个测试、exit 0 |

第一条实测最阴——它连失败都不报，只是那部分的测试数不变。所以**每次改完测试，看一眼 `Ran N tests` 的 N**，这是唯一不会骗你的数字。

## 8. ⚠️ 同名劫持：`my_math.py` 在两个目录里各有一份

`python -m unittest ...` 的模块搜索路径第 0 位是**当前工作目录**。这个坑我实测了：在根目录放一份「故意返回 999」的 `my_math.py`，`_t9/` 里放另一份，然后从根目录跑 `_t9` 里的测试：

```
AssertionError: 999 != 3
```

`_t9/my_math.py` 里的 `add` 返回 `"被根目录那份骗了"`，但测试拿到的是**根目录那份的 999**。也就是说：

> **测试导入的不一定是你以为的那个文件。** 目录里同名模块一旦被 `sys.path` 抢先命中，你测的是「另一个版本」，绿灯红灯都和你正在改的代码无关。

防护：

```python
import my_math
print(my_math.__file__)     # 打印出来，确认路径是你改的那份
```

把这一行放进测试的 `setUpClass` 里，或至少在调试时打一次。你的 `lreaning` 目录里 `game/` 和根目录**都有过同名 `.py`**（`ship.py` 只在 `game/`，`my_math.py` 在根目录），以后真要两边同名，`__file__` 是唯一可靠的自证。

## 9. 顺带：`my_math.py` 和标准库 `math` 不冲突

命名容易担心「会不会把 `math` 顶掉」。实测：

```python
import my_math, math
print(math.sqrt(16), my_math.add(1, 2))   # 4.0 3
```

模块名是 `my_math`，不是 `math`，所以没事。**但别真的给文件起名 `math.py`/`random.py`/`json.py`/`numbers.py`**——那样 `import math` 会拿到你的文件，报错还会发生在 pandas/matplotlib 内部，你根本找不到是自己造成的。这条是「重名劫持」的反面教材版。

## 10. `__pycache__` 里那个 `.pyc` 是什么

```
__pycache__/
├── my_math.cpython-315.pyc
└── test_my_math.cpython-315.pyc
```

`my_math.cpython-315.pyc` 是 `my_math.py` 的**字节码缓存**：第一次 `import` 时生成，之后源码没改（按 mtime/size 判断）就直接读它，加快导入。

- 它**不会**让你的修改失效（改了 `.py` 会自动重新生成），所以「改了没生效」不要怪它。
- `.cpython-315` 里的 `315` 是 Python 版本号，换 Python 版本缓存自然分开。
- 该进 `.gitignore`：`__pycache__/` 和 `*.pyc`。别提交（PEP8 那份文档也提过项目结构约定）。

## 11. `assert` 和测试里的断言不是一回事

[my_math.py:8-9](file:///E:/python%E6%BA%90%E7%A0%81/python%E5%B7%A5%E4%BD%9C%E5%8C%BA/lreaning/my_math.py#L8) 用的是 `raise`，这是对的。别把校验写成 `assert`：

```python
def divide(a, b):
    assert b != 0, "不能除以0"      # 看起来等价，其实不等价
    return a / b
```

实测：

```
python _assert.py     -> AssertionError: 不能除以0        exit=1
python -O _assert.py  -> 5.0                          exit=0   ← assert 被整句删掉，除零没被挡住
```

`-O`（优化模式）会把所有 `assert` 语句从字节码里**删掉**。所以 `assert` 用于「开发期假设」，参数校验用 `raise ValueError`。测试文件里的 `self.assertXxx` 不受 `-O` 影响，别混淆——名字像而已。

## 13. 完整改进版（可整块复制运行）

```python
import unittest
from my_math import add, subtract, multiply, divide


class TestMathFunctions(unittest.TestCase):

    def test_add(self):
        self.assertEqual(add(2, 3), 5)
        self.assertEqual(add(-1, 1), 0)
        self.assertEqual(add(0, 0), 0)

    def test_add_float(self):
        self.assertAlmostEqual(add(0.1, 0.2), 0.3, places=10)

    def test_subtract(self):
        self.assertEqual(subtract(10, 5), 5)
        self.assertEqual(subtract(0, 7), -7)

    def test_multiply(self):
        self.assertEqual(multiply(3, 4), 12)
        self.assertEqual(multiply(-2, 3), -6)
        self.assertEqual(multiply(5, 0), 0)

    def test_divide(self):
        self.assertEqual(divide(10, 2), 5)
        self.assertEqual(divide(-6, 3), -2)

    def test_divide_by_zero(self):
        with self.assertRaises(ValueError):
            divide(10, 0)

    def test_divide_by_zero_float(self):
        with self.assertRaises(ValueError):
            divide(10, 0.0)


if __name__ == "__main__":
    unittest.main()
```

跑 `python -m unittest -v` 实测：

```
Ran 7 tests in 0.001s

OK
```

注意它和原版的差别只有：一个概念一个方法、补了负数/0/`0.0`、浮点单独用 `assertAlmostEqual`。**没有改 `my_math.py` 一行**——因为这一版只测「已经承诺的行为」，没测「还没决定的行为」（bool/字符串要不要拒绝留给第 6 节）。

## 14. 本文件要点清单

| 主题 | 结论 |
|---|---|
| 跑测试 | 认 `Ran N tests`，不认「没报错」 |
| 收集规则 | 前缀是 `test`（不是 `test_`），类必须继承 `TestCase`，文件要 `test_*.py` |
| `assertRaises` | 不带 `with` = 永远绿灯（实测返回 `_AssertRaisesContext`） |

| `assert` vs `raise` | `python -O` 会删掉 `assert`（实测行为差异） |
| 一个测试一件事 | 一个方法只测一个概念，红了才知道为什么红 |

```python
    def test_add_table(self):
        for a, b, expected in [(2, 3, 5), (-1, 1, 0), (0, 0, 0), (99, 1, 100)]:
            with self.subTest(a=a, b=b):
                self.assertEqual(add(a, b), expected)
```

`subTest` 的价值：普通 `for` 里第一个失败就停，后面三组根本没测；用 `subTest` 四组都会各报一次。
